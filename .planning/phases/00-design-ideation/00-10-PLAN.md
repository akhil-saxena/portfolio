<objective>
Build the two case-study page templates and render every drafted study through them, so
DSGN-02 is satisfied by a template laid out against real text lengths rather than by a
wireframe against placeholder blocks.

Purpose: no case-study page has ever existed in this repository and the handoff contains no
design for one — that void is exactly why DSGN-02 exists. D-40's entire justification for
length-realistic drafts is that build phases work against real text lengths, so a template
laid out against lorem or against six-word stubs proves nothing about line length, heading
rhythm, or where a screenshot needs to sit. D-39's two tiers become two templates.

Output: two case-study sketches, a build-time copy loader, contact-sheet entries, and the
template decisions appended to the public design notes.
</objective>

Write `src/lib/copy.mjs` as a build-time loader using `node:fs`. It reads a named file from
`.planning/phases/00-design-ideation/00-COPY/`, splits the YAML frontmatter from the body,
and returns the frontmatter fields plus the body split into its H2 sections keyed by heading
text. Follow the fail-loud convention: throw with a message naming the file and the missing
heading if a study does not carry the four headings its tier requires. A silently-missing
section would render as a template that looks fine and proves nothing.

Do NOT copy the Markdown into the playground. Read it in place, so the sketch and the
committed draft cannot drift and so editing a draft is a one-file change.

Create `src/pages/case/long.astro` as artefact `X-case-long`, rendering BOTH long-form
studies — the design system and Cairn — through ONE template. Rendering only one would not
prove the template fits the tier; the point of the tier split is that a single template
carries both.

Lay it out against the real prose:
- Page header: Playfair `--text-4xl` 44px with an IBM Plex Mono eyebrow above it at
  `--text-xs` 11 and `--ls-wide`, carrying the project name and its D-45 status badge
- Prose measure capped at 68ch, using DM Sans `--text-md` 15 at `--lh-relaxed` 1.55
- Section headings from the Markdown H2s, as Playfair `--text-3xl` 40 at `--lh-snug`, with a
  `Divider` between sections
- A hero figure at the top and one or two inline figures with captions where the drafts'
  `## Assets` section says a screenshot belongs (D-41)

Render the `[NEEDS AKHIL]` blocks VISIBLY — do not hide or strip them. They are the point:
their length is what makes the template judgeable, and a reviewer must be able to see that a
paragraph-scale gap occupies a paragraph-scale slot. Give them a distinct but unobtrusive
treatment, such as an `--ink-3` muted colour with a left hairline in `--rule`, so they read as
provisional without breaking the measure. Render the `[source: <file>]` markers as small mono
annotations so provenance is visible during review, and note in the template that these are
review scaffolding that Phase 6 strips.

Compose from design-system components — `Heading`, `Text`, `Eyebrow`, `Divider`, `Badge` —
never from bespoke markup where a component exists. Zero `client:*` directives: all of these
are hook-free and the public hydration budget is zero.

Close the design-system study with its page-pointing sentence intact — it is the only project
whose outcome the reader is looking at while reading it, and the template must not truncate
that closing.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| committed Markdown drafts → rendered sketch pages | Prose authored from five repositories is rendered into HTML. The rendering is build-time and local, but the same prose ships publicly in Phase 6. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-00-24 | Tampering | provisional prose shipping as final | mitigate | `[NEEDS AKHIL]` blocks are rendered VISIBLY rather than stripped, and `[source:]` annotations are rendered as visible review scaffolding. A draft that still carries gaps therefore cannot be mistaken for finished copy at review. The notes record explicitly that Phase 6 strips the annotations, so the removal is a planned step rather than an accident. |
| T-00-25 | Tampering | the sketch and the committed draft drifting apart | mitigate | `src/lib/copy.mjs` reads the Markdown IN PLACE from the committed phase directory and writes nothing. There is no duplicated copy to fall out of date, and editing a draft is a one-file change. The loader throws when a required section is missing, so a structural divergence fails the build rather than rendering a misleading template. |
| T-00-08 | Repudiation (reputational) | unsourced claims rendered as finished prose | mitigate | Every factual claim in the drafts carries a `[source: <file>]` marker asserted by plans 05 and 06, and this plan renders those markers visibly so a reviewer can audit provenance on the page rather than in the source. |
| T-00-23 | Denial of Service (performance, self-inflicted) | a hydrated case-study page | mitigate | Zero `client:*` directives, asserted per file; `check-no-js.sh` gates the build. Every component used is hook-free. |
| T-00-04 | Information Disclosure | accidental commit of the playground | mitigate | `.playground/` is gitignored. Only the appended section of `00-PUBLIC-DESIGN-NOTES.md` is committed from this plan. |
| — | Spoofing | — | not applicable | Public editorial pages with no authentication, session or credential surface. |
| — | Elevation of Privilege | — | not applicable | No privilege boundary; no adapter, api route or binding is introduced. |
| — | Input Validation (ASVS V5) | — | not applicable | The only input is Markdown authored in this repository at a fixed path. No user input is accepted and no HTML is injected from an untrusted source; the loader renders text through design-system components rather than through raw HTML insertion. |
| T-00-SC | Tampering | npm/pip/cargo installs | not applicable | This plan installs no package. |
</threat_model>
