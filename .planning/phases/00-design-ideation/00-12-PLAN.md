**Scope guard (D-02).** These are sketches, not production application code. No Cloudflare
adapter, no CI wiring, no `src/pages/api` route, no auth, no D1 binding, no database. The
draft/ready/published states are *depicted from fixtures*, never implemented. If a task feels
like it is building Phase 7, it has left scope.

**How `?state=` actually works.** `astro build` with `output: 'static'` evaluates
`Astro.url.searchParams` at build time, where it is always empty — so `dist/` carries the
`populated` state of every route and nothing else. That is exactly what the build-time gates
(`check-no-js.sh`, `check-bundle.mjs`, `check-css-size.mjs`) need to measure. The **other**
states are rendered per-request by `astro dev`, which serves each request through the page
component with a real `Astro.url`. Review (plan 16) and screenshots (plan 17) therefore run
against `astro dev`, and `check-states.mjs` in task 2 proves the mechanism works rather than
assuming it. Do not attempt to emit a static page per state — that multiplies routes by six
and breaks the one-file-per-screen contract the coverage generator depends on.

**Why this plan waits on plan 11.** `.playground/` is a single serial build resource — one
`node_modules`, one `dist/`, one dev-server port — and plan 11 holds it open for a blocking
human review. Building concurrently underneath that review would produce a flaky checkpoint.
Plan 11 also settles two public-surface judgements the admin sketches inherit (the 44px-versus-52px
header and the `--ochre-d-strong` treatment), so its outcome is a real input here rather than a
scheduling artefact. Plans 12 to 16 are serial for the same single-resource reason.

The legacy React components referenced below live on the `legacy/nextjs-portfolio` branch and
are reachable ONLY via `git show legacy/nextjs-portfolio:<path>`.

`AppShell`'s prop contract, read from `../design-system/src/layout/AppShell/index.tsx:10-32`:

```ts
export interface AppShellProps {
  sidebar: ReactElement<{ collapsed?: boolean; onToggleCollapse?: () => void }>;
  topbar: ReactNode;
  main: ReactNode;
  footer?: ReactNode;
  storageKey?: string | null;
  sidebarWidth?: number;   // @default 240
  className?: string;
  style?: CSSProperties;
}
```

Four slots — `sidebar | topbar | main | footer`. **There is no `banner` slot**, which is G-8.
`sidebarWidth` defaults to 240; UI-SPEC's compact target is 208.

Two SSR behaviours to note rather than work around: `readStorage()` guards
`typeof window === "undefined"`, and `useState` + `useEffect` mean the collapse state renders
at its initial value under SSR. Both are fine for a sketch.

Hook-free (safe to render statically): `Chip`, `Text`, `Heading`, `Card`, `Link`, `Divider`,
`Eyebrow`, `Button`, `Badge`, `Timeline`, `StatCard`, `AppBar`, `Footer`, `EmptyState`,
`StatusPill`, `ProgressBar`.
Hook-using: `SegmentedControl`, `Lightbox`, `DataGrid`, `Sheet`, `Sortable`, `RichText`,
`AppShell`, `ConfirmDialog`, `Wizard`, `InlineEdit`, `FileInput`, `Modal`.

`AppShell` uses hooks, so it renders under SSR at its initial state with no hydration — which
is what a static sketch wants.

`StatusPill.stage` is the closed union
`"wishlist" | "applied" | "screening" | "interviewing" | "offer" | "closed"`
(`dist/index.d.ts:1020`). It cannot express draft/ready/published (D-13) or the pipeline
states (D-15). That is G-5, already registered; use `Badge` and record the substitution.

Compact density targets, from UI-SPEC §Density: **30px controls · 32px rows · 208px sidebar**,
against measured DS defaults of 36px input, 44px row, 240px sidebar. Measured token coverage
in `../design-system/src/primitives.css`: 0 of 95 height declarations, 13.5% of padding and
10.8% of gaps use a spacing token, and `Button` sets `padding: "7px 14px"` as an inline style
object unreachable by CSS at any specificity.
