<objective>
Capture every reviewed artefact as a committed screenshot, put the whole set in front of a human
for UI-SPEC's six review passes, then delete `.playground/` and assert it is gone.

Purpose: D-02 makes the playground throwaway and names *"a Phase 0 exit task that deletes the
directory"* as a **mandatory** scope fence — without an adapter, without CI, and without
surviving on disk, it cannot silently become the Phase 2 foundation. But the design work is the
phase's deliverable, and D-02's fence would otherwise destroy the only evidence of it. UI-SPEC
resolves that: screenshot **before** deletion into a committed directory, so a review comment,
a finding and a Phase 7 reference all still resolve to something after the code is gone. The
order is the whole plan — capture, then review, then destroy — because the deletion is
irreversible and the playground is gitignored, so nothing is recoverable from history by design.

Output: a committed screenshot record, a human sign-off, and an absent directory.
</objective>

<structural_note>
This is the phase's exit plan. It is the **only** plan that deletes anything, and its deletion is
irreversible: `.playground/` is gitignored on purpose, per RESEARCH OQ-2 adopted as UI-SPEC
Confirm-or-Override item 13, because a committed-then-`git rm` playground stays recoverable in
history — which is exactly what D-02's fence exists to prevent.

Task order is load-bearing and must not be reordered: **capture (task 1) → human review
(task 2) → delete (task 3)**. Capturing after review would risk shooting a set the reviewer
never saw; deleting before review would destroy the subject of the review.

`?state=` variants are served by `astro dev`, not by `astro build` — see plan 12's structural
note. The capture therefore runs against a dev server, which is also the only way the
non-populated states are reachable at all.

Playwright is already installed in `.playground` from plan 07 and its Chromium is cached.
</structural_note>

| `P- R-` (admin, phone) | charcoal **LIGHT** | `comfortable` | 390 x 844 |

**The six review passes** (UI-SPEC), walked top to bottom, one question per pass:

| # | Pass | The question being answered |
|---|------|----------------------------|
| 1 | Coverage table | Is any cell blank, or any `n/a` reason unconvincing? |

**Derive the capture list; never hand-list URLs.** Build it from `CANONICAL_IDS` plus each admin
route's own `STATES` export, reusing the glob logic plan 16 already wrote for the coverage
matrix. A hand-maintained URL list is the one mechanism guaranteed to silently omit an artefact
added late, and this capture is the last chance to record anything at all.

Apply the per-class viewport and mode contract exactly:
- `S- E- T- O-` — 1440 x 900, charcoal light, compact.
- `P- R-` — 390 x 844, charcoal light, **comfortable**. Compact never applies below the phone
  breakpoint, because 30px controls sit under the 44px touch floor D-09 implies.
- `X-` — charcoal **dark**, comfortable, captured at **both** 1440 x 900 and 390 x 844.

Capturing an admin artefact in dark mode is an anti-pattern rather than a preference: the light
palette is where the DS-02/DS-03 contrast failures live, and dark hides them. Assert the mode
per class in the script rather than trusting the page default, so a page that lost its
`data-brand` attribute fails the capture instead of producing a quietly wrong PNG.

Take **full-page** screenshots, not viewport-clipped ones. Several artefacts — the 39-photo
grid, the 11-bullet résumé entry, the conflict diff — are taller than 900px, and a clipped
capture would record the top of the screen the review passes are about.

Wait for network idle and for fonts to settle before each shot. The three Fontsource families
load as variable fonts with `font-display: swap`, so a capture taken too early records the
fallback stack and makes the typography review worthless.

Name every file exactly `00-{class}-{id}-{state}-{mode}-{viewport}.png`. Follow the fail-loud
