FIELD COMPOSITION — plan 13's idiom, one shape, no variants:
  <Field label="Title" wiring={wiring("f-<record>-title")}>
    <TextInput id="f-<record>-title" defaultValue={...} />
  </Field>
  - `Field` supplies the label. `TextInput` does not. Using both renders the label twice.
  - `defaultValue`, NEVER `value`. A static sketch has no onChange and React's controlled-input
    warning is not something to ship into a reviewer's console.
  - `wiring` is built by hand in frontmatter — `Field` wants the output of `useField` and an
    Astro page cannot call a hook. `FieldWiring` is a plain interface:
      { controlId, hintId: undefined, errorId: undefined, describedBy: undefined,
        invalid: false }
    Ids unique across the page: `f-<record-id>-<field>`.
  - `Field` + `Select` ALSO needs `ariaLabel`, duplicating the visible label: `Field` emits
    `<label for>` with no id of its own and `Select`'s trigger is a `role="combobox"` button,
    which is not a labelable element.
  - Two columns at >= 673px, one below. Sub-forms two-up at >= 375px.
  - Vertical rhythm: `--space-4` between fields, `--space-6` between groups, `--space-8` at
    section breaks. Use the tokens; never a literal. `density-compact.css` owns control heights.

OVERLAY COMPONENTS SERVER-RENDER TO ZERO BYTES. `Modal`, `ConfirmDialog` and `Sheet` each
render **0 B** — they mount through `DSPortal`, which returns null until a mount effect. **
`AlertBanner` and `FormErrorSummary` DO render.** Reach for those two, never for a dialog, on a
statically-rendered sketch.

THE OMISSION RULE (00-ADMIN-IA §EXIF sub-form): missing fields are OMITTED ENTIRELY, never
rendered as an em dash. A `—` beside `f/11` reads as a data bug, not as an absence. The admin
renders an empty field as empty and editable; the public surface renders nothing at all.

D-18 is lenient: an error message is about *publishing*, saving still works, and the message
attaches to the field it is about. Say "saving still works" in the body text — a reviewer
cannot see it otherwise.
