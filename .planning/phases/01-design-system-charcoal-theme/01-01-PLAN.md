**(a) E1 — the tone axis must reach ochre.** The design system declares seven `--amber*`
tokens and charcoal currently declares none, so `tone="accent"`, `Card variant="amber"`,
`Divider accent="amber"`, `Link`'s hover and `Timeline`'s dot all resolve the design system's
`#fbbf24` on a warm charcoal field. It is invisible to contrast testing because `#fbbf24`
measures roughly 11:1 on `#161616` — it passes every bar while being the wrong colour.

Enumerate the family from source rather than from this list, so a token added upstream since
planning is not missed:
`grep -oE '^[[:space:]]*--amber[a-z0-9-]*' src/tokens.css | tr -d ' \t' | sort -u`.
Expect exactly: `--amber`, `--amber-d`, `--amber-ink`, `--amber-l`, `--amber-soft`,
`--amber-vivid`, `--amber-warm`.

Declare each one in **both** charcoal blocks as a `var()` alias onto the corresponding ochre
token, not as a duplicated literal — the design system's own pattern, and the pattern the rest
of this file already uses for `--ink-4`, `--page-bg`, `--paper`, `--panel2`, `--rule-s` and
`--focus`. The mapping follows the ownership allowlist's own wording, *"`--ochre*` (the
charcoal accent, replacing `--amber*`)"*, and Rules C-1, C-2 and C-6 of the token contract:

| `--amber*` | charcoal alias | Why this one |
|---|---|---|
| `--amber` | `var(--ochre)` | Both are the fill-only accent. Rule C-1. |
| `--amber-d` | `var(--ochre-d)` | Both are accent-as-text and both feed focus. Rule C-6. |
| `--amber-ink` | `var(--ink-inverse)` | The ink that sits **on** a filled accent. Rule C-2 fixes it at `#161616` for an `--ochre` fill in both modes, and this file already declares `--ink-inverse` that way. |
| `--amber-l` | `var(--ochre-l)` if this file declares one, otherwise `var(--ochre)` | Soft tint. **Check the file first**; if no `--ochre-l` exists, alias to `--ochre` and say so in the comment rather than inventing an unmeasured tint value. |
| `--amber-soft` | same rule as `--amber-l` | Same reasoning. |
| `--amber-vivid` | `var(--ochre)` | `--amber-vivid` is documented as static in both modes (charts, badges, status dots); `--ochre` is `#B0722A` in both modes, so the aliasing preserves that property exactly. |
| `--amber-warm` | `var(--ochre)` | No separate warm ochre was measured. Alias and note it. |

Two hard constraints on this edit. **Do not introduce a new hex value.** Every alias must
resolve to a token this file already declares with a Phase-0-measured value; if the table
above would require a colour that does not exist here, alias to the nearest one that does and
record the substitution in an inline comment. And **do not touch `--focus`** — Rule C-6
prohibition 2 keeps it bound to `--ochre-d`, and aliasing `--amber-d` onto `--ochre-d` is
consistent with that rather than a second route into it.
