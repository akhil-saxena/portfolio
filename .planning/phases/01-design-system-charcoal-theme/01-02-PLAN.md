<objective>
Build the charcoal render harness: a brand axis in Storybook, and a reusable computed-style
probe in the Playwright suite. Then use it to prove the one property the whole theme rests on —
that charcoal resolves to its declared value in dark mode **regardless of stylesheet emission
order**.

Purpose: this plan is deliberately second, before any component fix, because it is what makes
every later plan's verification honest. Nine of the fifteen E-items are *"the source says X but
the rendered result is Y"* findings — E3, E5 and F-12-2 are literally about inline styles
beating class rules — and this repository's own recent history records a visual suite that
**hid failures** and had to be fixed. A grep gate on a component fix would reproduce exactly
that. After this plan, `<verify>` blocks downstream read pixels and computed values.

It is also D-37's foundation. D-37 gives charcoal full snapshot parity — every component, both
modes, both brands — at the accepted cost of a doubled baseline count. The **axis** lands here;
the 488-plus-charcoal **capture** lands in 01-20, after the component fixes, so baselines are
recorded once against finished behaviour instead of being re-recorded after every plan.

Output: a brand global, a probe helper, and one spec that reproduces Phase 0's 272-assertion
cascade result inside the design system's own CI.
</objective>

`default` so no existing story changes appearance and none of the 488 baselines move. Import
`../src/themes/charcoal.css` statically at the top of the preview, next to the other three

`brand: charcoal` that hardcoded wrapper background is wrong and would sit behind every

`var(--cream)`, which resolves `#1c1917` under the default brand and `#161616` under charcoal —

the `context.globals.backgrounds?.value === DARK_BG` dark-detection branch, both of which are

<task type="auto">
  <name>Task 2: Write the reusable computed-style probe helper</name>
  <files>../design-system/tests/visual/computed.ts</files>
  <action>
Create `tests/visual/computed.ts` exporting one function that every later plan in this phase
calls instead of hand-rolling its own `page.evaluate`. Nine plans need this; nine hand-rolled
copies would drift.

Signature — keep it exactly this shape so downstream plans can be written against it:

`probeComputed(page, opts)` taking `{ story: string; brand: "default" | "charcoal"; mode:
"light" | "dark"; selector: string; props: string[]; index?: number }` and resolving to a
`Record<string, string>` of computed values for the first (or `index`-th) element matching
`selector`, plus the resolved value of any entry in `props` that begins with `--` read via
`getComputedStyle(el).getPropertyValue(name).trim()`.

Behaviour it must have, each for a reason already measured in this repository:

- Navigate to `iframe.html?id=${story}&viewMode=story` with the brand and mode applied. Try the
  Storybook `globals` query parameter first; if it does not take on Storybook 8.6, apply
  `document.documentElement.dataset.brand` and `classList.toggle("dark", …)` directly inside a
  `page.evaluate` **before** reading, and record which path was used.
- Wait for `#storybook-root` with `state: "attached"`, not `visible` — `control-chrome.spec.ts`
  documents that Lightbox stories auto-open a dialog that hides the root from the
  accessibility tree, and `visible` times out on them.
- Wait for fonts: `await page.evaluate(() => document.fonts.ready)`. Font metrics change layout
  height, and a probe that races font loading returns geometry that is not reproducible. This
  matters more than usual in this phase, because 01-04 replaces the entire face layer.
- **Throw, loudly, when the selector matches nothing.** A probe that silently returns an empty
  object turns every downstream assertion into a tautology — the same class of failure as the
  baselines that "compared clean forever". The message must name the story, the selector and
  the brand/mode combination.
- Return raw computed strings (`rgb(176, 114, 42)`), not parsed colours. Downstream assertions
  compare against `rgb()` triples so a failure message shows the actual paint.

Also export a small `hexToRgb(hex: string): string` so downstream specs can write the token
contract's hex values literally and compare against Chromium's `rgb()` output without each
plan re-implementing the conversion.

Add nothing else to this file. It is a helper, not a spec — it must contain no `test()` call,
so it cannot be the thing that passes.

**Then make `npm run typecheck` actually cover it.** Verified at planning time: `tsconfig.json`
includes only `src/**/*` and `tsconfig.test.json` includes only `src/**/*.test.ts`,
`src/**/*.test.tsx`, `src/**/*.stories.tsx` and `src/test-setup.ts`. **Zero files under `tests/` are

same hole, one directory over. Confirm the addition took by running

count is zero the include did not match.

Write `tests/visual/brand-probe.spec.ts`, which reproduces the load-bearing half of Phase 0's
cascade probe inside the design system's own suite. Phase 0 ran 17 tokens × 4 constructed
import orders × 2 colour modes twice, for 272 green assertions, against a **live hazard** — the
default emitted order in that stack put the design system's `:root.dark, .dark` chunk *before*
the charcoal chunk, which is the ordering that loses charcoal entirely in dark mode when the
invariant is broken.

Three assertions:

**(a) Anchor tokens resolve to their declared values in all four brand × mode cells.** Use
`probeComputed` on any cheap always-present story. The two anchors Phase 0 named, plus the two
this phase added:

| Token | charcoal light | charcoal dark |
|---|---|---|
| `--cream` | `#f4f1ea` | `#161616` |
| `--ochre-d-strong` | `#6b4417` | `#d4a66d` |
| `--amber` | `#b0722a` | `#b0722a` |
| `--panel` | `#fbf9f4` | `#1e1e1d` |

And under `brand: default`, `--cream` must still be `#f5f3f0` light / `#1c1917` dark — the
assertion that charcoal is scoped and has not leaked.

**Assert the declared value, not merely that the cells agree.** Phase 0's own note on this is
the reason: cross-cell agreement alone would also pass if `data-brand` were misspelled
everywhere, or if the charcoal sheet stopped being imported at all — every cell would agree on
the design system's neutral values and the probe would go green while measuring nothing.

**(b) Order-independence.** Phase 0's mechanism was constructing four import orders in a
consumer. That is not reproducible inside Storybook, and faking it would prove nothing. Instead
assert the property that makes order irrelevant, in the browser rather than in source: for
every custom property the charcoal light block declares, `getComputedStyle` under
charcoal × dark returns the **dark** declared value, i.e. no property is falling through to a
`:root.dark` value. Read the two name sets out of `src/themes/charcoal.css` with the same
parser plan 01-03 uses, resolve each in both modes, and assert every one differs from the
design system's neutral where the contract says it should and equals charcoal's where it says
it should. That is the observable consequence of exhaustiveness, and it is what "regardless of
which stylesheet the bundler ordered first" means at runtime.

**(c) The negative control, and it must be verified to bite.** Delete the single `--wire`
declaration from the charcoal **dark** block — the exact control Phase 0 used. Re-run (b) and
confirm it fails, naming `--wire`. Restore the line, confirm `shasum -a 256` of
`src/themes/charcoal.css` matches the value taken before the deletion, and confirm the spec is
green again. Record both SHA-256 values and the failure message in the SUMMARY. A negative
control that was described but not run is worth nothing, and this is the one Phase 0 proved
reproduces on demand.

Do not add charcoal screenshots here — D-37's capture is plan 01-20, after the component fixes.
This spec asserts computed values only, so it stays fast and has no baseline to go stale.
