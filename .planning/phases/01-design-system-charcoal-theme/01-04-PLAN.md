<objective>
Split font delivery out of the token layer (D-29), and make the split actually worth something by
**removing** the 15 `@fontsource` `@import` lines from `src/tokens.css` (D-36). Ship the charcoal
face layer, relocate the four pre-existing families to `fonts/default.css` so nothing is deleted,
and add the family-name-to-`@font-face` agreement gate that D-29's loud-failure design does not
cover.

Purpose: **this is the breaking half of v2.0.0** and the reason the release is a major. It is also
the single most misreadable item in the phase, so it is worth stating flatly:

> A consumer assembling the D-33 manifest today emits **81** `@font-face` rules — the design
> system's 73 plus charcoal's 8 — because the manifest *must* import `tokens.css` for the values
> charcoal overrides, and that inlines all 73 faces. Shipping `fonts/charcoal.css` while leaving
> `tokens.css` unchanged **adds 8 rules and removes none: strictly worse than doing nothing.**

The 8-vs-73 win exists only in isolation. It survives at the consumer only if the faces come out
of `tokens.css`. That removal is what breaks Cairn, which gets its typography that way today, and
semver telling the truth is the mitigation — hence `fonts/default.css` and a one-line migration
rather than a hunt for four vanished families.

Output: three new/changed stylesheets, three new dependencies, one new CI gate, and a token layer
that bundles as tokens instead of as tokens-plus-73-faces.
</objective>

**The registered family names, and why the suffix is a hard requirement.** Fontsource's variable
packages register `'Playfair Display Variable'` and `'DM Sans Variable'` — not the plain names. A
charcoal token naming only `"Playfair Display"` while the face declares
`'Playfair Display Variable'` **silently renders Georgia, and the page looks almost right.** IBM
Plex Mono has no `Variable` alias, so its stack correctly names the plain family. Both names must
appear in the stack, Variable first, exactly as `src/themes/charcoal.css` already spells them.

**The check must resolve `var()` aliases, and a measurement proves why.** Phase 0's negative
control stripped `Variable` from `--font-serif`'s head; breaking **one** token surfaced **four** —
`--font-serif`, `--font-display`, `--display` and `--serif` — because three resolve through the
first. A per-token check that did not follow aliases would have reported one failure and left
three tokens silently rendering Georgia. `src/tokens.test.ts` already has a `resolve()` helper
that follows `var()`; use it.

**`src/tokens.test.ts` already walks every `.css` under `src/`** in its *"defines every custom
property referenced anywhere in src"* test. The two new font files declare no custom properties
and reference none, so they pass it trivially — but they must stay that way, which is what the
zero-custom-properties assertion below is for.
