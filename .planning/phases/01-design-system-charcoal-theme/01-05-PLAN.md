<objective>
Resolve **THEME-API open decision 1 — the italic axis** — as an explicit user decision, then
implement whichever way it goes and restate the recorded face baseline to match.

Purpose: this is the one item in Phase 1 that Phase 0 deliberately refused to decide, and the
reason it refused is methodological rather than aesthetic. `8` is a recorded acceptance criterion
and a measured baseline; changing what "8" measures mid-plan would have silently invalidated it.
So Phase 0 left it, in writing, as *"an open Phase 1 decision about what the face layer is for,
and it should be made explicitly rather than inherited by default."*

Inherited by default is exactly what happens if this plan is not a checkpoint. Option A is
already in the file, so silence ships it — and silence would ship two editorial-italic roles
rendering as a browser-synthesised oblique on an identity organised around an editorial serif.

This plan is small on purpose. It has one decision and one implementation, and it is separated
from 01-04 because a checkpoint and an implementation in the same plan is how a checkpoint gets
skipped.

Output: a closed decision, the face layer matching it, and every "8" in the repository restated
if the answer moves it to 12.
</objective>

<interfaces>
**The two editorial-italic roles**, from UI-SPEC:
1. the **22px Playfair display subtitle**;
2. the **22px italic serif cross-link** at the foot of Work and Photos — which Rule C-6 already
   singles out as the ambiguous case and rules must use `--ochre-d-strong`.

Both are Playfair Display. Under the current Option A face layer, both render as a
**browser-synthesised oblique** — a mechanical slant of the roman outlines — rather than
Playfair's drawn italic, which has genuinely different letterforms.

**The exact cost of Option B**: add one line,
`@import "@fontsource-variable/playfair-display/wght-italic.css";`, to `src/fonts/charcoal.css`.
That contributes **4** more `@font-face` rules (the same four subsets as the roman axis: cyrillic,
vietnamese, latin-ext, latin), moving the recorded baseline from **8** to **12**. It requires no
new package — `@fontsource-variable/playfair-display` is already installed by 01-04 — so there is
no supply-chain surface to this option at all.

**Where "8" is currently recorded**, all of which move to 12 under Option B:
- the face-census assertion in `src/tokens.test.ts`'s `font delivery` describe (01-04 task 3);
- the per-entry-point table in that same test;
- the `src/fonts/charcoal.css` header, which states *"The four entry points below produce 8 face
  rules (4 + 2 + 1 + 1)"* and separately carries the `KNOWN GAP` paragraph describing this very
  decision;
- the `EDITING THIS FILE` warning in that header, which says the checks *"require exactly four
  at-rule inclusions"* — that becomes five.

**What does NOT change either way**: no token value, no family name in any `--font-*` stack (the
italic axis is selected by `font-style: italic`, not by a different family name), no package, no
export entry, and no contrast ratio.
</interfaces>

Does the charcoal face layer ship Playfair Display's **drawn italic**, or keep the roman axis only

  </decision>
  <context>
Phase 0 measured everything about this and deliberately did not decide it, because `8` was a
recorded acceptance criterion and moving what "8" measures mid-plan would have invalidated it
silently. THEME-API lists it first among *"three decisions this document surfaces rather than
resolves."*

The two affected roles are both 22px Playfair: the display subtitle, and the italic serif
cross-link at the foot of Work and Photos. Today both render as a synthesised oblique — the
browser slanting roman outlines — rather than Playfair's drawn italic, which has different
letterforms, not merely a slant. On an editorial serif identity that difference is visible, and
the cross-link is a navigational element rather than decoration.

This costs nothing in dependencies: `@fontsource-variable/playfair-display` is already installed.
It is one `@import` line. The entire cost is face-rule count and the download of one more woff2
when an italic actually renders.
  </context>
  <options>
    <option id="option-a">
      <name>Option A — roman only, baseline stays 8</name>
      <pros>
No change to any file. The recorded baseline of 8 stands, so every Phase 0 number carries forward
unrestated. Four `@font-face` rules fewer, and one fewer woff2 that a page could request. Simplest
possible face layer.
      </pros>
      <cons>
Both editorial-italic roles ship as a synthesised oblique. On a serif identity this is visible,
and it is visible on precisely the two elements the identity is most about — an editorial subtitle
and a serif cross-link. It also means the site cannot honestly claim to be showcasing Playfair
Display, which weakens the project's core value that the site is the proof the design system works.
      </cons>
    </option>
    <option id="option-b">
      <name>Option B — add the italic axis, baseline moves to 12</name>
      <pros>
Playfair's drawn italic renders for both roles. One line, zero new packages, zero new tokens, no
contrast or token change. Fixes a visible identity defect on the two elements that most express
the identity. The extra download happens only on pages that actually render an italic serif.
      </pros>
      <cons>
The recorded face baseline moves from 8 to 12, and **every downstream comparison must be restated
against 12** — the test assertion, the per-entry-point table, and two paragraphs of the
`fonts/charcoal.css` header including its `EDITING THIS FILE` grep count. Four more `@font-face`
rules, of which three are non-latin subsets the site will never request (their `unicode-range`
never matches this content). Still 12 against the design system's 73.
      </cons>
    </option>
  </options>
