<objective>
Close **G-15 / DS-09**: give every component a JS subpath export, so a public island can import one
atom without dragging the editor and drag-and-drop stacks into the browser.

Purpose: this is the second half of success criterion 5, and it is the one gap in this phase that
was already proven **not fixable by configuration**. One `import { Chip }` rendered `client:load`
emitted a client chunk of **570,555 B raw / 176,922 B gzip / 99 modules**, containing ProseMirror
×10, TipTap ×23, lowlight ×4, highlight.js ×4, dnd-kit ×3 and lucide-react ×43 — from that single
import and nothing else. Three configuration fixes were attempted during research and **each
produced byte-identical output**: `sideEffects: false`, removing the leading `"use client"`
directive from `dist/index.js`, and marking the module-scope `var lowlight = createLowlight();` as
`/* @__PURE__ */`.

So the per-component-subpath branch is not a contingency, it is the live branch. And the fix is
**upstream, in this repository, never a local workaround in the portfolio** — Phase 5 re-checks the
result as a gate, and `/photos` is the only hydrating public route in the whole roadmap, so this is
what makes PUB-14 and QUAL-01 reachable at all.

One stack fact to hold onto: Astro 7 ships **Vite 8, which is Rolldown-based**. Tree-shaking
semantics are Rolldown's, not Rollup's, and Rollup-era advice about `sideEffects` and `@__PURE__`
does not transfer — that is precisely why the three research fixes measured byte-identical. Any
verification that matters therefore has to run through the real consumer toolchain, not only
through esbuild.

Output: 81-ish new subpath entries, a fast CI gate, and a re-measurement with the same script that
produced the finding.
</objective>

chunks keeps the module graph correct even if a bundler reaches a chunk by another route. New
