<objective>
Close **E2** (`AppShell.collapsed` is an output, not an input; `--ds-sidebar-w` is inline; one
hardcoded breakpoint) and **G-8** (no slot for a persistent strip).

Purpose: `AppShell` is the admin's frame, and every one of these four gaps was measured by living
with the consequence across seven admin routes.

**E2, precisely.** The gap is not "no responsive posture" — it is that `AppShell` has **exactly one,
hardcoded, at a width that is not a class boundary**, and its content is "hide the sidebar". The
767px breakpoint **bisects device class 3 (673–884px)**, so one device class gets two different
layouts. Three mechanisms compound it: there is no `collapsed`/`defaultCollapsed` prop;
`cloneElement` **overwrites** any consumer-supplied `collapsed` on the sidebar child; and
`--ds-sidebar-w` is written as an **inline style on the shell's own root**
(`style="--ds-sidebar-w:208px"` in the emitted HTML) with `sidebarWidth` fixed at construction — so
**no media query can drive it.** That last point is why UI-SPEC's 208px compact target *"needed zero
declarations because it is unreachable at all."*

**G-8, precisely.** Slots are exactly `sidebar | topbar | main | footer`, so D-15's persistent
pipeline strip was composed **into the topbar** — and *"the strip does not survive as a distinct
region. It is welded to the topbar's own layout, it shares one row of the shell with the global
publish action, and it has no landmark of its own"*, so a screen-reader user can only reach it by
walking the topbar. Both alternatives are worse in the way D-15 forbids: `main` makes each of seven
routes reimplement it (the divergence D-15 rules out), and `footer` puts an active-process indicator
below the fold. It was **re-tiered from `backlog` to `should-fix-in-Phase-1`** precisely because it is
a trivial additive optional prop.

Output: one component, four gaps, every change additive.
</objective>

```tsx
export interface AppShellProps {
  sidebar: ReactElement<{ collapsed?: boolean; onToggleCollapse?: () => void }>;
  topbar: ReactNode; main: ReactNode; footer?: ReactNode;
  storageKey?: string | null;   // default "ds-sidebar-collapsed"; null disables persistence
  sidebarWidth?: number;        // default 240
  className?: string; style?: CSSProperties;
}
```

The three lines that are the finding:

```tsx
const [collapsed, setCollapsed] = useState<boolean>(() => readStorage(storageKey));

const sidebarWithProps = React.cloneElement(sidebar, {
  collapsed,                                        // ← unconditionally overwrites the child's own prop
  onToggleCollapse: () => setCollapsed((c) => !c),
});

style={{ "--ds-sidebar-w": collapsed ? "48px" : `${sidebarWidth}px`, ...style }}   // ← inline; unreachable by CSS
```

Rendered structure: `div.ds-atom-appshell[data-sidebar-collapsed]` containing
`header.ds-atom-appshell-topbar`, `aside.ds-atom-appshell-sidebar`, `main.ds-atom-appshell-main`, and
optionally `footer.ds-atom-appshell-footer`. It is a CSS Grid, so a new row is a grid-template change
in `primitives.css` inside the AppShell banner section.

`readStorage` is already SSR-safe (`typeof window === "undefined"` → false) and the persistence
effect is already try/catch-guarded. Preserve both.

**`--ds-sidebar-w` is in `src/tokens.test.ts`'s `COMPONENT_SCOPED` allowlist** — the regex
`^--(ds-sidebar-w|ds-snackbar-offset|ov-[a-z0-9-]+)$` — documented as *"set inline by a component on
its own subtree, as a documented knob"*. Moving the declaration to class level means that comment
becomes inaccurate; update it, and keep the allowlist entry (the property is still declared outside
`tokens.css`). Plan 01-12 extended the same regex for `--ds-appbar-h` and declared it at class level
for exactly this reason — follow that precedent.

**The 767px breakpoint** lives in `primitives.css` (`display: none` on the sidebar below 767px), not
in the component. **Device class 3 is 673–884px**, so 767 falls inside it.

**Out of scope:** the `data-density` axis, `Button`'s inline padding, `--control-h` / `--row-h` /
`--field-gap` — all **G-2 / DS-11 → Phase 06.1**. This plan makes the sidebar width *reachable*; it
does not add a density axis to drive it.

  <action>
Run the sibling protocol §1 gate; confirm `charcoal-theme`.

**Controlled/uncontrolled.** Add `collapsed?: boolean` and `onCollapsedChange?: (c: boolean) => void`,
plus `defaultCollapsed?: boolean`. Follow the pattern `Lightbox` already uses in this codebase, and
copy its precedence rule so the library is internally consistent: **controlled when the consumer
supplies the value**; the internal state owns it otherwise. `Lightbox` requires *both* value and
handler to be controlled; for a boolean where a consumer may legitimately want to pin the state
without observing changes, `collapsed != null` alone is the better trigger. Whichever you choose,
document it in the docstring and say why it differs from `Lightbox` if it does.

Precedence when several sources disagree, decided here rather than emergent:
`collapsed` prop > `defaultCollapsed` (initial only) > `storageKey` value > `false`.

**Stop `cloneElement` from overwriting the child.** This is the literal E2 defect. The child's own
`collapsed` prop must win when `AppShell` is not controlling — pass the injected value only when
`AppShell` is the source of truth, or read the child's existing props and prefer them. Preserve the
`onToggleCollapse` injection either way: that is the mechanism the sidebar uses to *report* a toggle
and it was never the problem.

**Move `--ds-sidebar-w` out of the inline style.** Declare it in `primitives.css` on
`.ds-atom-appshell`, with the collapsed value under `[data-sidebar-collapsed="true"]` — the attribute
is already emitted, so the state is already expressible in CSS. Then a media query, a consumer rule,
or a future density axis can all reach it, which is the whole point.

`sidebarWidth` (a number, default 240) cannot survive as a fixed inline value and still be
media-query-driven — those are contradictory requirements. Resolve it: when `sidebarWidth` is passed,
keep writing it inline as an author-level override (it is an explicit consumer instruction and should
win); when it is **not** passed, write nothing inline and let the class-level default apply. That way
the default is reachable and an explicit value is still honoured. **Document the tradeoff on the
prop**, because a consumer who passes `sidebarWidth` and then wonders why their media query does
nothing needs to read the answer there. This is the sentence that makes UI-SPEC's 208px target
achievable: omit `sidebarWidth`, set `--ds-sidebar-w` from CSS.

Update the `COMPONENT_SCOPED` comment in `src/tokens.test.ts` — it says these properties are *"set
inline by a component on its own subtree"*, which is no longer the whole truth for `--ds-sidebar-w`.
Keep the allowlist entry.

The SSR and localStorage behaviour must not regress. `readStorage`'s `typeof window` guard and the
try/catch in the persistence effect both stay; add a test asserting server-rendered markup for the
uncontrolled default is unchanged, since this component is the admin's frame and a hydration mismatch
there would be expensive.

**G-8 — the banner slot.** Add `banner?: ReactNode` rendered between the topbar and main as its own
element with its own landmark. The finding's core complaint is not layout, it is that the strip *"has
no landmark of its own"* — so the element must be independently reachable.

Get the landmark right. A `<section aria-label="…">` with an author-supplied label is a landmark;
a bare `<div>` is not, and `role="banner"` is **wrong** — that role means the page header and there
must be only one, which the topbar already is. Add `bannerLabel?: string` with a sensible default so
the region has an accessible name (an unlabelled `section` is not exposed as a landmark by most
screen readers, which would silently reproduce the finding). Document that pairing: the slot only
solves the finding if it is labelled.

Render **nothing** when `banner` is absent — follow the existing `{footer && <footer …>}` pattern
exactly. An always-present empty region would add a landmark to every existing consumer's
accessibility tree.

Update `.ds-atom-appshell`'s `grid-template-areas` / `grid-template-rows` in the AppShell banner
section of `primitives.css` to carry the new row, and make it work in all four `banner` × `footer`
combinations. Grid rows do not disappear because a slot is empty, so a naive fixed template leaves a
gap; drive the template off the presence of the elements (or emit a `data-has-banner` attribute and
switch on it). Test all four combinations — that is why it is in the behaviour list.

The banner must **persist**, not scroll with main. Only `.ds-atom-appshell-main` is the scroll
container, which the existing layout already establishes; verify the banner sits outside it.

**The breakpoint.** `primitives.css` hides the sidebar below **767px**, which bisects device class 3
(**673–884px**), so one device class renders two ways. Decide and record:

- **Preferred: remove the hardcoded rule and let the consumer own it.** The consumer knows its device
  classes; the design system does not. With `--ds-sidebar-w` now reachable and `collapsed`
  controllable, a consumer can express any posture — which is precisely what tasks 1 and 2 just made
  possible, so this is the coherent ending. Document the removal in the docstring with a one-line
  example of the media query a consumer would write.
- **Acceptable fallback: keep a default but make the width configurable**, so the value can be moved
  off a class boundary.

**Removing the rule is a behaviour change for any existing consumer relying on it.** This release is
already a major, so that is affordable — but it must be **named in the changelog entry** alongside
the font relocation, not slipped in. If you keep the rule instead, say why in the SUMMARY.

Add a story exercising the banner slot with a realistic persistent strip, so 01-20's snapshot parity
and `test:a11y` both cover the new markup and landmark. Run `npm run test:a11y` on the AppShell
stories: a duplicate `banner` role, an unlabelled landmark, or an empty region all surface there.

Commit as `feat(appshell): controllable collapse, reachable sidebar width, and a banner slot`, with a
