<objective>
Close **E7** and the three `DataGrid` findings that travel with it: the hardcoded
`density="comfortable"`, the unremovable selection column, the hardcoded *"Job applications"*
accessible name, cell stringification, and the unconditional unstyled pager.

Purpose: `DataGrid` is the admin's photo grid, and Phase 0 measured **three stacked causes** for a
row that could not reach its target height:

1. `DataGrid` pins `density="comfortable"` on its own `Table.Root` with no prop and no inheritance,
   and `table.css`'s `.ds-atom-table[data-density="comfortable"] .ds-atom-table-row` is specificity
   **(0,3,0)** against a consumer's (0,2,0) — so a consumer's row rule **never applied to anything**.
2. Once it does apply, `height` on a `<tr>` is a **minimum**: forcing the declaration to `8px` still
   measured 35px.
3. The content floor is set by **a selection column the consumer did not ask for and cannot remove** —
   `SelectAllCell` and a `SelectCell` per row render unconditionally, `onSelectionChange` is optional
   but the column is not, and its 22px checkbox label accounts for **7 of the 9px overshoot**.

**Scope split, stated plainly.** The finding's proposed fix is *"a `density` prop on `DataGrid`, a
`--row-h` custom property in `table.css`'s density modes, and a `selectable` prop"* and adds *"all
three are G-2 / DS-11 territory."* That is true of the **`--row-h` token layer**, which is Phase
06.1's. It is **not** true of the two **props**: E7 is in this phase's queue and a component that
cannot be told its own density is an API gap regardless of what tokens exist. So this plan ships the
props and the reachability; Phase 06.1 ships the geometry tokens that drive them. Recording that
split is part of the plan's job.

Output: five prop-level gaps closed on one compound component, with the density *token* work left
where it belongs.
</objective>

Two private lookups drive cell rendering and are the mechanism behind G-5's second surface:

```ts
const STATUS_BADGE: Record<string, {label: string; tone: BadgeTone}> = { applied, interviewing, offer, rejected }
const PRIORITY_COLOR: Record<string, string> = { high: --red-vivid, medium: --amber-vivid, low: --green-vivid }
```

A `Badge` can only reach a row through a column keyed **exactly** `status`, and then only with one of
those four job-domain values. `--amber-vivid` in `PRIORITY_COLOR` is mapped to ochre by 01-01, so it
already renders correctly under charcoal — no change needed there.

There is also a design note at line 17: *"`<Pagination>` is rendered as a SIBLING of the inner
`Table.Root`"* — read it before restructuring, it explains the DOM shape.

**F-13-3's measurements:** neither `pagination.css` nor `iconbutton.css` is named by `datagrid.css`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consumer cell values → the DOM | Allowing a `ReactNode` into a cell replaces string coercion with rendering, which is a real change in what can enter the tree. |
| column key → private behaviour | A column *named* `status` currently triggers a job-domain lookup. Action-at-a-distance keyed on a string. |
| generated per-component CSS → a consumer's page | A compound component whose sheet is incomplete renders visibly broken and only at the consumer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Tampering | cell rendering | accept | `React.isValidElement` gates on an element the consumer constructed; React escapes text children. `DataGrid`'s consumers here are this project's own committed JSON. No HTML string is ever accepted — that stays out, and D-20's stored-XSS reasoning is why. |
| T-14-02 | Spoofing | the `status` column | mitigate | The job-domain badge and dot mappings become **opt-in presets** on the column definition rather than firing on a key match, so nothing renders a job-domain badge by accident. |
| T-14-03 | Spoofing | accessible names | mitigate | `ariaLabel` has no `"Job applications"` fallback; the default is neutral or the prop is required, with the choice recorded and named in the changelog if breaking. |
| T-14-04 | Denial of service | table structure | mitigate | Turning off the selection column shifts every row's cell count and any `colSpan`; asserted in the behaviour list and re-checked by `test:a11y`, which catches header/body cell-count disagreement. |
| T-14-05 | Denial of service | consumer CSS | mitigate | Sheet dependencies declared by the generator (preferred) so they cannot go stale, plus a test asserting the known compounds. |
| T-14-06 | Elevation of privilege | Phase 06.1's scope | mitigate | `--row-h` and the density **token** layer stay out; the pager's touch target stays out with the explicit reasoning that no `IconButton` size can reach 44px. |
