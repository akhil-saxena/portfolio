export function DSPortal({ children, target }: DSPortalProps) {
  const [mounted, setMounted] = useState(false);

**`DSPortal` — the escape hatch.** Add `inline?: boolean`. When true, return `<>{children}</>`
directly: no `mounted` gate, no `createPortal`. When false or absent, behave exactly as today.

The finding proposes two shapes — *"an `inline` / `portal={false}` escape, or an SSR-safe `DSPortal`
that renders in place and adopts on mount"*. **Take the first.** The adopt-on-mount variant means
every overlay renders in the consumer's DOM position and then relocates, which changes stacking
context and focus order between the two frames and would put a hydration mismatch in eight
components. `inline` is opt-in, so a consumer takes the tradeoff knowingly.

**Document the tradeoff on the prop**, because it is real: an inline overlay lives inside the
consumer's DOM, so it is subject to ancestor `overflow`, `transform` and `z-index` — which is exactly
the coupling D-310 chose `document.body` to avoid. The prop's docstring is where a consumer learns
that it exists for **server-rendered and no-JS reachability**, and that a normal client-side dialog
should not use it.

Thread `inline` through the overlays that consume `DSPortal` and are named in the finding — `Modal`,
`ConfirmDialog`, `Sheet` — and through `TypeToConfirm` if it wraps one of them rather than
`DSPortal` directly. **Do not** add it to `Lightbox` (01-07 owns that component and there is no
server-rendered lightbox use case), and do not add it to `Tooltip` / `Popover` / `HoverCard`, whose
whole behaviour is positioning against a trigger.

**`Modal` — `closable`.** Add `closable?: boolean`, default `true`. When false, suppress **all three**
exits together: the header Close button, the Escape handler, and the backdrop click path. The
finding's proposed fix says *"together"* and that word is the substance: suppressing only the button
leaves two silent exits and the dialog still is not fail-closed, which is worse than not having the
prop because it *looks* solved.

For Escape, do not reach around `useDismiss`. Either skip registration when `closable` is false, or
register and no-op. Whichever you choose, assert with `__dismissStackSize()` that the stack still
returns to zero on unmount — a layer that registers and never unregisters would break Escape for
every dialog opened afterwards, which is precisely the regression that hook exists to prevent.

Add the accessibility consequence to the docstring: a non-closable dialog is a **trap by design**, so
the consumer must provide its own path out (a re-auth form, a sign-out button). Say that explicitly.
An undismissable dialog with no action in it is an accessibility failure, and the prop should not
read as innocuous.

Extend `src/smoke.test.tsx` — or add an SSR-specific test — asserting each overlay renders **> 0 B**
with `inline` and **0 B** without. Both directions: the 0 B assertion is what proves the default is
unchanged, and Phase 0 measured 0 B twice for a reason.
