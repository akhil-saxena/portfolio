<objective>
Build **`FocalPointPicker`** — the component G-1 / E12 names — so the admin's 39-photo gallery can set a
crop focal point without every consumer re-implementing it.

Purpose: this is a **new component**, and its tier pairing is the reason it is here. G-1 carries **two**
tiers, `backlog` **and** `blocks-Phase-7`, and the register is explicit that the pairing is the entire
reason the tier vocabulary was widened: *"tagged `backlog` alone they read as 'optional, revisit
someday', which is how a Phase 7 blocker goes missing."* The orchestrator has scoped it into this phase
so it ships with the release Phase 7 will already be consuming, rather than needing a second major.

**The cost of its absence was measured, not estimated.** The local prototype a consumer is forced to
write is **419 lines — 269 non-comment**, of which 86 are the 3:2 frame CSS ported from legacy and 183
are TypeScript and JSX. *"That is the cost of the absence: every consumer that wants a focal point
rewrites all 269 lines and re-chooses the interaction model while doing it."*

**And the three legacy defects are the specification**, each read out of the legacy source and each
measured in Chromium against the built `dist/`:

1. **Mouse-only.** The legacy control binds `mousedown` only, so it is inert to touch **and to pen**.
2. **Keyboard-unreachable.** No `tabIndex`, no key handler — *"the only stored crop in the product
   cannot be set without a mouse."*
3. **Uncleaned listeners.** `document` listeners removed on mouse-up only, so an unmount mid-drag
   leaks them.

Output: one accessible component, built from design-system primitives, replacing 269 lines per
consumer.
</objective>

**Measured prototype behaviour, which is the acceptance target:**

| Input | Measured result |
|---|---|
| pointer drag to (25%, 75%) | `object-position` moved `50% 25%` → `25% 75%` |
| `↑ ↑ →` from `50% 25%` | `51% 23%` — so a fine step is 1% horizontal, 1% vertical per press |
| `Shift+↓` from `51% 23%` | `51% 33%` — so Shift is a coarse step of 10% |
| `Home` | `50% 50%` — reset to centre |
| readout | `role="status" aria-live="polite"` |
| listeners | aborted through an `AbortController` on unmount |
| console | zero console errors, zero page errors across the whole run |

**The one interaction-model divergence, recorded rather than slipped in — read this before choosing:**

> The legacy control drags the **image**, with an inverted delta and an arbitrary `/ 2` damping factor,
> so the same drag means a different value on a 320px frame than on a 640px one. The prototype places
> the **focal point** directly, which is frame-size independent.

**Take the prototype's model** — place the point, do not drag the image. The finding itself says *"that
two reasonable engineers pick different models for one CSS property is itself the argument for the
component living upstream"*, so choosing deliberately and documenting the choice is part of closing it.
Record the rejected model and why in the component docstring, not only in the SUMMARY: the next person
to touch this will otherwise re-derive it.

**Composition rule.** The finding's proposed fix is *"New `FocalPointPicker` built from DS primitives,
keyboard-operable via arrow keys."* **Built from DS primitives** is a constraint: use existing
components and tokens rather than hand-rolling chrome, and if a primitive is missing, that is a finding
for the SUMMARY rather than a licence to inline.

**Where it goes.** `src/inputs/FocalPointPicker/` — it is a form control that produces a value.
01-08's entry scan picks it up automatically from `src/*/*/index.tsx`; **01-12's count assertion fails
by name** if it is exported without being catalogued in `src/OverviewPage.tsx` and counted in
`README.md`.

**Aspect ratio.** D-23's case is a **3:2** frame, and the legacy CSS for it was 86 of the prototype's
269 lines. Do not hardcode 3:2 — take it as a prop with 3:2 as the default, and implement it with
`aspect-ratio` rather than the legacy padding-hack, which is most of why those 86 lines existed.

**Out of scope:** the 44px touch floor for the marker handle is *not* excluded — this is a **new**
component, so it must meet the floor from the start rather than inheriting F-15-7's debt. Build it
right the first time.

  <action>

Create `src/inputs/FocalPointPicker/index.tsx`.

**Props**, minimal and controlled — this is a form control and the consumer owns the value:
`value: { x: number; y: number }` (percentages), `onChange: (v) => void`,
`src: string` and `alt: string` for the preview image, `aspectRatio?: number` defaulting to 1.5 (3:2),
`label: string` for the control's accessible name, plus `className`.

**Pointer, not mouse.** Bind `pointerdown` / `pointermove` / `pointerup` with `setPointerCapture`, one
code path for mouse, touch and pen. This is legacy defect 1, and `Lightbox`'s swipe in 01-07 chose the
same mechanism for the same reason — a touch-only implementation is inert to a pen.

**Place the point; do not drag the image.** Compute the value from the pointer's position within the
frame's bounding rect as a percentage. No delta accumulation, no damping factor, no inversion — that is
the rejected model, and it is what makes the legacy control frame-size dependent. The eighth behaviour
is the assertion that pins this.

**Keyboard.** `tabIndex={0}`, `role="slider"` is tempting but wrong for two axes — use
`role="application"` only as a last resort, and prefer a plain focusable element with a clear
`aria-label` plus the live readout below, which is what the prototype measured working. Bind
`ArrowUp/Down/Left/Right` at 1%, the same with `shiftKey` at 10%, and `Home` to reset to centre. Match
the measured steps exactly — they are the recorded acceptance values.

`preventDefault` on the arrow keys so the page does not scroll while adjusting, but **only when the
control has focus**, so a page-level scroll is never stolen.

**Clamp at every entry.** Pointer, keyboard and a controlled `value` prop from outside can all deliver
an out-of-range number. One clamp function, applied at all three.

**Cleanup through `AbortController`.** Pass its signal to every `addEventListener` and abort it in the
effect's cleanup, so a mid-drag unmount cannot leak — legacy defect 3, and the prototype's measured
solution. Assert it: render, start a drag, unmount, and verify no listener fires afterwards.

**CSS in a `DS atom: FocalPointPicker` banner section** of `primitives.css`, using `aspect-ratio` for
the frame rather than the legacy padding hack — that hack was most of the 86 CSS lines the prototype
had to port. Use design-system tokens for the frame border and the marker; **the marker's hit target
must meet 44px** even if its visible dot is smaller (a transparent expanded hit area). This is a new
component, so it starts compliant rather than joining F-15-7's queue.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consumer-supplied `src` | An image URL reaches an `img` element. Same class as `Lightbox`'s in 01-07. |
| pointer listeners → document lifetime | The legacy control leaked `document` listeners on a mid-drag unmount. A new component repeating that is a memory and correctness bug in the admin. |
| a new component → the published API | Once exported it is API forever; its interaction model and value shape cannot be changed without a major. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01 | Denial of service | leaked listeners | mitigate | Every `addEventListener` takes an `AbortController` signal aborted in cleanup — the prototype's measured solution to legacy defect 3 — with a mid-drag unmount asserted in tests and zero console errors asserted in the browser run. |
| T-19-02 | Spoofing | accessibility claim | mitigate | Operation is proven **by keyboard alone** in a real browser against the exact measured sequence, and by a **touch** pointer — neither of which a jsdom test can assert. `test:a11y` covers the name, the role and the `alt`. |
| T-19-03 | Tampering | the value | mitigate | Clamped to 0-100 at all three entry paths (pointer, keyboard, controlled prop); frame-size independence asserted at two frame widths, which is the recorded divergence from the legacy model. |
| T-19-04 | Repudiation | the interaction-model choice | mitigate | The rejected model (drag the image, inverted delta, `/2` damping) and the reason are recorded in the component docstring, not only in the SUMMARY — the finding notes two reasonable engineers pick differently. |
| T-19-05 | Tampering | consumer `src` | accept | React escapes the attribute; a `javascript:` URL does not execute on an `img`. Consumers here are the project's own committed JSON. |
| T-19-06 | Denial of service | announcement flood | mitigate | The live region is throttled during drag (announce on `pointerup` and per keyboard step), with the choice documented — an un-throttled region on `pointermove` produces either a flood or nothing useful. |
| T-19-SC | Tampering | npm/pip/cargo installs | mitigate | **No install.** Built from DS primitives and native pointer events; a drag library would be a new supply-chain surface for arithmetic. |
</threat_model>
