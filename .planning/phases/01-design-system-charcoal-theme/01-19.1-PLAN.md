<objective>
Make the visual baseline set trustworthy **before** a human reviews it at 01-20.

Two defects, both discovered by measurement during this phase, both of which would corrupt the
capture gate rather than merely inconvenience it.

**E29 — 67 story files hardcode `className="dark"`.** `src/tokens.css` declares its dark block as
`:root.dark, .dark`, so a nested wrapper carrying that class **re-declares roughly 50 neutral dark
tokens below the brand layer**, while `src/themes/charcoal.css` is scoped to `:root[data-brand=…]`
and cannot reach inside. `.storybook/preview.tsx:126-134` states the consequence in measured terms:
`--cream` resolves to **`#181818` instead of charcoal's `#161616`**, and `--wire` to
`rgba(255,255,255,0.22)`. So **a charcoal-dark capture of any such story pins the wrong brand while
still looking plausibly dark.** `preview.tsx:136` already fixes its own wrapper
(`className={isCharcoal ? undefined : "dark"}`) and its comment says plainly that it cannot guard
per-story decorators. This plan closes that hole.

01-18 hit this as a live trap, not a theoretical one: `inputs-badge--dark-mode` and
`inputs-statuspill--dark-mode` each set `className="dark"` **and** a hardcoded `#1c1917` page, and
they are precisely the two stories a badge-colour review would open first. It avoided them by
asserting the brand on the probed element.

**F-19-3 — the baseline directory has drifted 75%.** Measured by 01-19: `tests/visual-baselines/`
holds **240 directories and 240 PNGs** (204 light, 36 dark), while the built Storybook index holds
**502 stories**. **444 stories have no baseline directory at all, and 186 of the 240 directories name
story ids that no longer exist.** The running "01-20 owes N baselines" figure — currently **21** — is
a tally carried forward in summaries, *not* a number derivable from disk. Recording 21 captures into
a set that is 75% incomplete and 37% orphaned produces a review artefact nobody can trust.

Output: no story owns its mode, a guard that keeps it that way, a reconciled baseline directory, and
a capture list for 01-20 derived from disk.
</objective>

<interfaces>
<!-- Read out of $DS/.storybook/preview.tsx at planning time. -->

The mode/brand mechanism already exists and is correct. `preview.tsx` declares two toolbar globals,
`theme` (`light`/`dark`) and `brand` (`default`/`charcoal`), and **one decorator applies both in a
single pass** to `document.documentElement`:

```tsx
document.documentElement.classList.toggle("dark", isDark);
if (isCharcoal) document.documentElement.dataset.brand = "charcoal";
else document.documentElement.removeAttribute("data-brand");
```

Its comment records why one pass: splitting them across two decorators "paints a frame in the wrong
brand, which is the flash D-34's no-flash module exists to remove — and it would make every
first-frame screenshot unreliable."

**Every `.dark` rule in the system is written with a descendant combinator**, so all of them still
match from `<html>`. That is the whole reason a per-story wrapper is unnecessary as well as harmful.
A story that wants dark should therefore request it through the **global**, not through markup.

`initialGlobals` sets `brand: "default"` deliberately — "charcoal must be opt-in so none of the
recorded visual baselines move." Preserve that.
</interfaces>
