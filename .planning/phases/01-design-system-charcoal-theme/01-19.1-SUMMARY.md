## Task 1 — the real offender set, and the shapes in it

The plan carried 01-16's figure of "67 story files". That is right for one shape and there are five.

**Ground truth came from the TypeScript AST, not a grep.** The naive counts and the real ones differ, and the difference is exactly the trap this phase has shipped five times:

| | naive grep | TS AST (real) |
|---|---|---|
| `className="dark"` | 72 occurrences / 67 files | **69 JSX attributes / 67 files** |
| `#1c1917` | 81 occurrences / 69 files | **78 string values / 69 files** |

The three excess `className="dark"` matches are 2 JSDoc comments (`StatusPill.stories.tsx:123`, `ConfirmDialog.stories.tsx:289`) and 1 docs code sample inside a template literal (`CommandPalette.stories.tsx:52`). **71 files carried at least one shape; 70 were changed** (DotGrid deliberately not).

### The five shapes

| # | Shape | Count | Disposition |
|---|---|---|---|
| S1 | `decorators`/`render` wrapper `<div className="dark" style={{ background: "#1c1917", … }}>` | 64 files | class dropped, hex → `var(--cream-2)`, `globals: { theme: "dark" }` added |
| S2 | wrapper `className="dark"` with no hex (`Sortable` via a `DarkDemo()` helper, `AppShell` with `height: 100vh`) | 2 files | class dropped, globals added; `Sortable`'s `var(--cream, #1a1410)` left, already token-driven |
| S3 | `globals: { backgrounds: { value: "#1c1917" } }` — dark selected by **hex-matching preview.tsx's chrome constant** | 4 stories | → `globals: { theme: "dark" }` |
| S4 | meta-level `parameters.backgrounds.values` palettes listing `dark: #1c1917` **and pinning `default: "white"`** | 5 files | **left** — see finding 2 |
| S5 | decorative demo canvas `background: "#1c1917"`, no `.dark` class (DotGrid, ×2) | 1 file | **left** — see finding 1 |

S3 is worth calling out: those four stories were *already* getting `<html>.dark`, because `preview.tsx:113` treats `globals.backgrounds.value === DARK_BG` as dark. They worked, by hex coincidence, and they are the only converted stories whose rendering did not move.

### The mechanism, proven before the bulk change

The plan asked whether story-level `globals` actually drives `preview.tsx`'s decorator in Storybook **8.6.18**. It does, and the repo already used it — `TokenCheck.stories.tsx:424` carries `globals: { theme: "light" }`. Measured on `inputs-button--default` before touching anything:

| URL globals | `html.class` | `data-brand` | `--cream` | `--ochre` |
|---|---|---|---|---|
| *(none)* | `""` | `null` | `#fcfcfc` | `""` |
| `theme:dark` | `dark` | `null` | `#181818` | `""` |
| `theme:dark;brand:charcoal` | `dark` | `charcoal` | **`#161616`** | **`#b0722a`** |
| `brand:charcoal` | `""` | `charcoal` | `#f4f1ea` | `#b0722a` |

Then **one** story (`Badge`) was converted, the edit proven by `git diff` rather than asserted, and re-probed:

```
GLOBALS="theme:dark;brand:charcoal"
  darkEls: ["HTML(html)"]          ← the story's own DIV is gone
  deepest: --cream=#161616  --wire=#727268  --ochre=#b0722a
```

Only then were the remaining 66 files converted, by a TS-AST codemod applying 205 edits back-to-front (69 class deletions, 67 hex swaps, 4 globals rewrites, 68 globals insertions), plus two hand edits (`Sortable`'s helper-rendered wrapper; `CommandPalette`'s docs sample, which was teaching the defect as the recommended recipe).

### E29 measured in both directions

**Pre-fix, live, `brand=charcoal theme=dark`, at the deepest node** — three stories, identical result:

```
html:    class="dark" brand=charcoal  --cream=#161616     ← the root is right
.dark:   HTML(html) | DIV             ← the story's own wrapper
deepest: --cream=#181818  --wire=rgba(255, 255, 255, 0.22)  --ochre=#b0722a
```

This is exactly the consequence `preview.tsx:126-134` documents, now confirmed rather than inherited. **And it exposes a sharp edge the plan's brand-assertion advice does not cover on its own:** `--ochre` read `#b0722a` *correctly* at that node. The brand layer **did** apply; the neutrals were shadowed *underneath* it. So asserting the brand at the probed element is necessary and **not sufficient** — `brand-isolation.spec.ts` asserts both halves for that reason.

**Post-fix:** `--cream` `#161616`, `--wire` `#727268`, `.dark` = `["html(root)"]`.

### Default-brand rendering — the safety property, split in two

The plan's must-have says "Default-brand rendering is unchanged, so none of the recorded baselines move." **Measured, that is two claims, and only one of them holds.**

**Holds — token resolution is unchanged.** Across **10 unconverted stories × 4 brand/mode cells = 40 measurements**, before and after: **zero token or structural differences.** The only diffs were `body.bg` alpha values, and they flickered in *both* directions between runs (`rgb(252,252,252)` ↔ `rgba(245,243,240,0.016)`) — Storybook's backgrounds addon mid-transition, i.e. measurement noise, not an effect of the edit. At converted stories the deep `--cream` is `#181818` before *and* after: under the default brand a wrapper `.dark` and `<html>.dark` really do declare the same values, so removing the wrapper changes nothing about tokens. **The plan's argument is confirmed by measurement.**

**Does not hold — the page darkens, and 72 baselines move.** At the capture cell (`initialGlobals` = `theme: light`, `brand: default`) a converted story previously rendered a dark **island on a light page**:

```
inputs-badge--dark-mode
  before: html.cls=""      htmlCream=#fcfcfc  deepCream=#181818  dark=[DIV]
  after : html.cls="dark"  htmlCream=#181818  deepCream=#181818  dark=[HTML(html),DIV]
```

This is not avoidable: making a dark-mode story request dark through the global is *what puts the class on `<html>`*, which is the whole point, and that necessarily darkens the page the story used to leave light. The new rendering is the more correct one — a dark-mode story showing a dark page. **73 stories now pin `theme: "dark"`; 72 of them have a recorded baseline that will move; 1 (`display-rollingnumber--counter-light`) has none and is `TIME_DEPENDENT` anyway.** The 4 S3 stories are byte-identical before and after. The full 72-id list is in commit `380d979`.

`initialGlobals.brand = "default"` is untouched, so charcoal remains opt-in.

### One consequence 01-20 must know

**Story-level `globals` are authoritative over the URL for that axis.** Measured:

```
url="theme:light"                  -> {cls:"dark", brand:null}       (story pins dark)
url="theme:light;brand:charcoal"   -> {cls:"dark", brand:"charcoal"} (story pins dark)
```

So a converted dark story can no longer be switched to light from the toolbar — correct for a story whose subject is dark mode, and it was effectively true before via the hardcoded wrapper. **Brand is not pinned, so charcoal capture works.** A consequence for `probeComputed`: requesting `mode: "light"` on a converted story would fall through to its direct-DOM fallback, so `brand-isolation.spec.ts` only probes dark cells on those stories.

## The guard, and its three-way proof

`$DS/src/story-mode.test.ts`, 15 cases, collected by `npm test`.

**It parses with the TypeScript compiler.** I first wrote a hand-rolled comment stripper and **it was wrong** — it reported `Tabs.stories.tsx:301` as string content when it is a real JSX attribute, because `don't` in JSX text at line 288 opened a phantom single-quoted string and desynchronised everything after it. That is the ninth-plus instance of this phase's recurring gate defect, and I found it in my own gate before shipping it. The AST is immune to all four traps present in this repo (JSDoc prose, docs code samples in template literals, apostrophes in JSX text, escaped quotes in strings) by construction.

**Three-way proof:**

| | Result |
|---|---|
| **FAIL on the pre-plan tree** — `Badge.stories.tsx` restored from `cp` backup | RED, 2 assertions, naming `Badge.stories.tsx:110 className="dark"` and `:112 background: "#1c1917"`. The 13 other cases stayed green, so the failure is targeted, not blanket |
| **FAIL with the fix disabled** — same mutation against `brand-isolation.spec.ts` | RED with the E29 signature: `Expected "#161616" / Received "#181818"`, 1 failed / 9 passed |
| **PASS on shipped** | 15/15 and 10/10; `Badge.stories.tsx` restored and `shasum -a 256 -c` verified `OK` both times |

**Walking through it — recorded rather than claimed.** I tried ten reintroduction spellings:

| Attempt | Caught? |
|---|---|
| `className="dark"`, `className={"dark"}`, `` className={`dark`} ``, `className="p dark q"` | CAUGHT |
| `class="dark"`, `classList.add("dark")`, `classList.toggle("dark", …)`, `el.className = "dark"` | CAUGHT *(added after the first pass slipped)* |
| `className={"da" + "rk"}`, `className={clsx("dark")}`, `className={C}` | **SLIPS** — pinned as a known limit in a test |

The imperative detector initially flagged `preview.tsx`'s own `document.documentElement.classList.toggle("dark", isDark)` — which is the *correct* mechanism. It is now scoped to non-root targets, with fixtures asserting the root case stays legal and a scoped element is still caught. `preview.tsx`'s guarded wrapper is asserted present (`className={isCharcoal ? undefined : "dark"}`), asserted **not flagged** (its value is conditional, not literal), and its `background: "var(--cream)"` asserted intact.

The three slipping shapes are covered by a different instrument, not hand-waved: `brand-isolation.spec.ts` asserts in a browser that under charcoal `document.querySelectorAll(".dark")` is exactly `[html]`. That reads the DOM, so the spelling cannot matter.

## Findings raised (not fixed)

### 1. The system has no token for "a surface that is dark in both modes"

`DotGrid`'s two stories paint a fixed 480×240 canvas `#1c1917` because the component's entire subject is a decorative texture *on a dark hero panel*. `var(--cream)` follows the mode (white in light) and `var(--ink)` inverts, so neither survives. The hex is therefore load-bearing for the demo, and under charcoal that canvas will **not** track the brand. It carries no `.dark` class, so it cannot shadow the brand layer and E29 does not apply — but a charcoal reviewer will see a panel that is not charcoal's. Exempted explicitly in `story-mode.test.ts`, with a test asserting the exemption still describes reality.

### 2. Five story files pin a white page via `parameters.backgrounds.default: "white"`

`Calendar`, `DatePicker`, `DateRangePicker`, `ColorPicker`, `ColorInput` each declare a local `backgrounds` palette with `default: "white"` (`#ffffff`). Under charcoal light the page colour is `#f4f1ea`, so those stories render on a pinned white page that is not the brand's. Left alone because `preview.tsx` explicitly designates the `backgrounds` parameter *"Storybook's own chrome … brand-independent"*, and removing the override would move five more baselines for a chrome concern. Worth a decision at 01-20 rather than a silent fix.

### 3. `probeMeta` in `tests/visual/computed.ts` is per-worker, so a bare assertion on it can be vacuous

`playwright.config.ts` sets `fullyParallel: true` with 6 workers. A test that asserts `probeMeta.urlGlobals > 0` **without probing in that same test** can land in a fresh worker and read `0/0`. My first draft did exactly that and passed by luck; it now performs its own probe first. Any future spec reading `probeMeta` needs the same care.

### 4. A hand-rolled comment stripper cannot be trusted on these files

`don't` in JSX text (`Tabs.stories.tsx:288`) desynchronises a naive scanner and makes it misclassify real code as string content — I measured this in my own first attempt. Anything in this repo that must ignore comments should parse. This compounds 01-19's finding 1 (`declaredIn()` in `src/tokens.test.ts` does not strip comments at all): that function is still a grep over raw text.

### 5. `npm run check` rejects exports from a test file

Biome's `lint/suspicious/noExportsInTest` failed the first draft of `story-mode.test.ts`, which exported its three detectors for reuse. Nothing imported them, so the fix was to comply rather than suppress. Noting it because sharing a detector between two test files in this repo needs a non-test module.
