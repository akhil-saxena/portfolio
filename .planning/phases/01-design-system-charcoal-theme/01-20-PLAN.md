<objective>
Record charcoal's full snapshot parity (D-37), run every gate in the repository green on one commit, and
write the v2.0.0 changelog — then stop for a human to look at it before anything is published.

Purpose: **D-37 is a decision with a stated cost that was already weighed and taken**: *"Every
component, both modes, charcoal as well as the default theme. Nothing regresses unseen, and DS-06's
contrast contract gains a visual companion — a token can pass a numeric contrast assertion while looking
wrong. Accepted cost: doubled snapshot count and doubled review burden."*

That last sentence is why this plan is second-to-last rather than early. Baselines are recorded **once**,
against finished behaviour, after all seventeen component and token plans have landed. Recording them
earlier would mean re-recording after each plan, and re-recording is how a suite starts hiding failures —
which this repository's own history records happening.

The doubled review burden is real and it is a human's. `autonomous: false`.

Output: a complete baseline set, one all-green commit, a changelog a consumer can act on, and an
approval.
</objective>

`type === "story"`, visits `iframe.html?id=…&viewMode=story`, waits for `#storybook-root` with

style tag (because Playwright's `animations: "disabled"` waits for animations to *finish* and three of
this system's are infinite), and captures.

It already carries two hard-won properties that must be preserved:

- a `TIME_DEPENDENT` exclusion set of four RollingNumber stories, with a docstring insisting *"Prefer
  making a story deterministic over adding to this list"* and recording that two of three original

  to abort the run and everything after it went unchecked.

**Current baseline count: 488** files in `storybook.spec.ts-snapshots/`. D-37 roughly doubles it.

**`.storybook/test-runner.ts`** drives `test:a11y` and `test:visual:capture`; the brand global from
01-02 must reach it too, or the a11y sweep only ever runs the default brand.

**`playwright.config.ts`** has `timeout: 300_000` per test — five minutes for a loop over 145-plus
stories. **Doubling the story count may exceed it.** Raise the timeout, or split the loop into two tests
(one per brand), which also makes a failure report say which brand broke. Prefer the split: each test
stays inside the existing budget and the diagnostic improves.

**Every gate in the repository**, all of which must pass on the final commit:
`npm test` · `npm run check` · `npm run typecheck` · `npm run css:check` · `npm run test:visual` ·
