<interfaces>
**The exports are wildcards**, which makes the file rename free:

```json
"./themes/*.css": { "style": "./dist/themes/*.css", "default": "./dist/themes/*.css" }
"./fonts/*.css":  { "style": "./dist/fonts/*.css",  "default": "./dist/fonts/*.css"  }
```

So `src/themes/charcoal.css` → `monochrome.css` changes the public subpath with **no `package.json`
edit**. Confirm that holds rather than assuming it.

**Measured scope in the design system:** 37 files, 584 occurrences, 2 files to rename, and **504
baseline PNGs** whose filenames embed `--charcoal-`.

**The dangerous failure mode is a *partial* rename, not a missed one.** If `charcoal.css` declares
`[data-brand="monochrome"]` while `preview.tsx` still sets `charcoal`, the theme silently never
applies and every story renders in the default brand — which is exactly how a 508-story sweep once
passed while rendering the wrong brand. Gate on completeness, not on the happy path.
</interfaces>
