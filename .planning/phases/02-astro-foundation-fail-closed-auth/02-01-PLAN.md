<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → developer machine | `npm install` executes arbitrary `postinstall` code from a remote publisher; a typosquatted name compromises the machine and the build |
| npm registry → CI runner → Cloudflare deploy | Any package installed here is later installed by CI with a Cloudflare API token in scope; a malicious dependency inherits deploy credentials |
| slopcheck ecosystem auto-detection | A wrong ecosystem produces false `[SLOP]` verdicts (measured in Phase 0) and, worse, could produce false `[OK]` verdicts for a package that does not exist in npm |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-SC | Tampering | npm installs into the tracked repo root | mitigate | This plan **is** the mitigation: `slopcheck install -e npm` over all 16 packages, plus a non-auto-approvable human verification of every non-`[OK]` row against the live npm page, completed before `package.json` exists. 02-03 cites this file and installs nothing outside the approved set. |
| T-02-01 | Tampering | slopcheck ecosystem misdetection | mitigate | `-e npm` is mandatory on every invocation and the method note is copied into the audit file. Phase 0 measured the PyPI-default failure directly (6 of 8 false `[SLOP]`, including `react-dom`). |
| T-02-02 | Elevation of Privilege | `postinstall` scripts on dev dependencies | mitigate | `npm view <pkg> scripts --json` is checked per package and any `postinstall` is surfaced as its own audit column, so the human gate sees it rather than discovering it at install time. |
| T-02-03 | Spoofing | typosquatted scoped package names | mitigate | Task 2 step 3 names the four highest-risk scoped/hyphenated packages explicitly and requires publisher confirmation on the registry page, not on the audit table. |
| T-02-04 | Repudiation | audit drifting out of sync with what is installed | mitigate | The `key_links` must-have requires one audit row per package that 02-03 installs; 02-03's own verify greps this file. A package added later without a row fails that check. |
</threat_model>
