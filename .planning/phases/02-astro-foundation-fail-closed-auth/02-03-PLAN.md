<verify_idiom>
**Every `<automated>` block below uses one idiom, and it is deliberately not the default.** The
Bash tool does not set `-e`, so a `;`-joined chain ending in `echo OK` reports success no matter
what failed inside it — the exit status is the `echo`'s. `set -e` is not the fix either: under it
a negative control written `grep BAD && { echo …; exit 1; }` aborts the shell in the *passing*
case, because the `&&` list returns non-zero when `grep` finds nothing.

The idiom used throughout, with no `set -e`:
- **Positive assertion** — `CMD || { echo "<what failed and why it matters>"; exit 1; }`
- **Negative assertion** — `if CMD; then echo "<what was found and why it is wrong>"; exit 1; fi`

No command appears bare. Every step either exits non-zero with a diagnostic or falls through with
status 0, so the trailing `echo` is a marker rather than the thing being reported. If you add a
step, write it in one of those two forms.
</verify_idiom>
