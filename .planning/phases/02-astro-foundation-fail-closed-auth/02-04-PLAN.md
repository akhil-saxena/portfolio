<objective>
Create the three on-demand route surfaces this phase exists to protect — `/admin`, `/api/*` and
`/_actions/*` — and the single unguarded accessor for the R2 binding. Prove all three are rendered
on demand rather than prerendered, and prove `env.PORTFOLIO_BUCKET` resolves from
`cloudflare:workers` under `astro dev`.

Purpose: the roadmap's sequencing call is that **auth lands before the admin surface exists in a
deployed Worker**. That requires the surface to exist locally first, so auth has something real to
guard and the tests have something real to assert against. This plan creates that surface in a
state that is **never permissive**: every one of the three routes returns `503 Service
Unavailable` with a body stating auth is not yet wired. Not `200`, not a rendered admin page, and
deliberately not `401` either — because plan 02-07 must be able to write a genuinely failing test
that asserts `401`, and a stub that already returns `401` would let that test pass without any
auth code existing.

Nothing is deployed until plan 02-09. The window in which these routes exist without JWT
verification is entirely local, and it closes in the next wave.

Output: `/admin`, `/api/health` and `/_actions/ping` reachable on demand under real `workerd`,
absent from `dist/`, returning 503, with the R2 binding proven live.
</objective>

The exact shape of the unguarded binding accessor. Write this, do not derive it:

`src/lib/r2.ts` imports `env` from `cloudflare:workers` and exports one function,
`getPortfolioBucket(): R2Bucket`, that returns `env.PORTFOLIO_BUCKET` directly. `R2Bucket` is

Forbidden in that file, and asserted against by this plan's verify:
- `if (!env.PORTFOLIO_BUCKET)` or any truthiness check on the binding
- `env.PORTFOLIO_BUCKET?.` optional chaining

- a `try`/`catch` around the binding read
- returning `null`/`undefined` when the binding is missing

If the binding is genuinely absent the correct behaviour is a thrown error and a 500 — loud, in
the logs, traceable. That is the whole point of FND-03.

already proof, since it can only be produced if `.list()` succeeded.

failing test to drive the real implementation, and a 401-returning stub would satisfy that test
with no auth code behind it. 503 is nonetheless a refusal — there is no point at which this
endpoint returns a success status to an unauthenticated caller.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → `/admin`, `/api/*`, `/_actions/*` | Untrusted, unauthenticated requests reach these three prefixes; this is the boundary the whole phase exists to close |
| Worker → R2 `portfolio-photos` | The Worker holds a capability (the binding) that no client holds; anything the route echoes back is a disclosure decision |
| build output → public CDN | Any file in `dist/` is served by Static Assets *before* the Worker runs; a prerendered protected route is therefore a public file |
