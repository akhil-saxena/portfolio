<objective>
Turn Criterion 3 into machinery: a build that **fails, loudly** if any API or admin route was
prerendered into `dist/`, a ship path that fails if the design-system dependency spec is still a
local path, and a recorded negative control proving each gate actually bites.

Purpose: Criterion 3's phrase *"there is no path that degrades to permissive at runtime"* is a
claim about structure, and structure is only real if it has been observed to refuse. Phase 0
learned this the expensive way — four negative controls passed for the wrong reason before the
discipline of proving a control bites caught them. This plan therefore does two things of equal
weight: it writes the gates, and it deliberately breaks the build three times to watch each gate
fire, then restores the tree byte-identically.

The hazard being closed is composed, not simple. Astro prerenders everything under
`src/pages/api/*` **by default** unless `export const prerender = false` is set on each endpoint.
Separately, Cloudflare Workers Static Assets serve a matching static file **before the Worker ever
runs** unless the path is listed in `run_worker_first`. Compose the two and forgetting
`prerender = false` on one endpoint emits a static JSON snapshot of that route's build-time output
at that path — `requireAccess()` never executes, and the response *looks correct*. A smoke test
would pass. This is a second, differently-shaped fail-open path, additional to the legacy
cookie-presence fallback, and the only defence that scales past human memory is a gate in the
build.

This plan owns `package.json` for wave 4. Its wave partner 02-07 touches only `src/lib`,
`src/middleware.ts`, the three route files and `test/auth/`, so the two cannot collide.

Output: two gate scripts, wired so the route gate runs on every build and the dependency gate runs
only on the ship path, plus `02-NEGATIVE-CONTROLS.md` recording each control's observed failure.
</objective>

Read the `### Constraints` bullet on the cross-repo dependency in CLAUDE.md closely, because this
plan encodes a distinction it only implies:

> During development the portfolio consumes it as a **packed tarball** (`npm pack` →
> `file:*.tgz`), never `file:../design-system` or `npm link`. A CI gate fails the build if the
> dependency spec still starts with `file:` **at ship time**.

Those two sentences are in tension unless the gate is scoped. During Phase 5 development the spec
legitimately **is** `file:./local-packages/*.tgz`, and a gate that fired on every push would make
the sanctioned workflow impossible. So the gate is a **ship** gate: wired into the `deploy` script
and the deploy CI job, never into `build` or `check`. Regular CI runs it in advisory mode, which
reports the finding and exits zero — visible, not blocking. Getting this scoping wrong in either
direction is a real failure: enforce it everywhere and development stops; enforce it nowhere and a
symlinked React reaches production.

Note the gate is being built in Phase 2 even though **no design-system dependency exists yet**.
That is the point: FND-05 exists so that the moment Phase 5 adds the tarball, the machinery that
prevents it shipping is already in place and already proven to work.

The Phase 0 finding that makes the source-side check non-negotiable, and the grep hygiene rule:
@.planning/phases/00-design-ideation/00-FINDINGS.md

Two things carried forward. First, `grep -c` counts *lines, not matches*, and header prose in a
file can satisfy a naive grep — so a gate implemented as a bare grep can be self-invalidating.
Implement the checks in Node with comments stripped before matching. Second, macOS BSD `sed -i ''`
with a range address is a silent no-op that exits 0; if any step needs to mutate a file, use Node
or `perl -0pi -e`, never BSD `sed`.

<interfaces>
Both scripts are plain ESM Node scripts (`.mjs`), take an optional path argument so they can be
pointed at a fixture instead of the real tree, and print a message that names the requirement and
explains the consequence rather than only the symptom.

`scripts/assert-no-prerendered-protected-routes.mjs [distDir]` — default `./dist`. Two
independent checks, both must pass:
1. **Source side.** Every file under `src/pages/api/**` and `src/pages/admin/**` must contain an
   uncommented `export const prerender = false`. Strip `//` line comments, `/* */` block comments
   and `{/* */}` JSX comments before matching, so a commented-out declaration cannot satisfy the
   check. Skip files whose basename begins with `_` only if Astro itself ignores them — verify
   that against Astro's routing rules rather than assuming.
2. **Output side.** None of `<distDir>/api`, `<distDir>/admin`, `<distDir>/_actions` may exist as a
   directory, and no file may exist at `<distDir>/admin.html` or match
   `<distDir>/**/{api,_actions}/**`.
Exit 0 on pass. On failure print every offending path, cite AUTH-03, state that Static Assets serve
matching files before the Worker runs so auth never executes, and exit non-zero.

`scripts/assert-no-local-dep-specs.mjs [manifestPath] [--advisory]` — default `./package.json`.
Scans `dependencies`, `devDependencies`, `optionalDependencies` and `peerDependencies` for any spec
beginning `file:`, `link:` or `portal:`. Additionally, for each declared dependency, if
`node_modules/<name>` exists and is a symlink, that is a finding too — `npm link` leaves no trace
in the manifest, so a manifest-only check would miss the exact hazard CLAUDE.md names. On failure
print each offending package with its spec, cite FND-05, and state the reason: a symlinked or
locally-pathed package is not copied, which yields two React copies and intermittent "Invalid hook
call" errors that can vanish on refresh. Exit non-zero — unless `--advisory` is passed, in which
case print the same report prefixed as an advisory and exit 0.
</interfaces>
