<objective>
Convert the 13 stored résumé bullets from `<strong>`-bearing HTML strings to **bold-only inline
markdown**, and put the grammar that defines that phrase in exactly one module.

Purpose: this is the storage half of criterion 3, and it is the half that closes the legacy
stored-XSS class *structurally* rather than by filtering. The legacy app rendered bullets through
`dangerouslySetInnerHTML` in `Timeline.tsx:48` plus three admin components, with **no sanitiser
anywhere in the repository**. ADR-001's answer — which ADR-002 §2 explicitly preserved when it
reversed ADR-001's *editing* decision — is a stored shape that no HTML string can be expressed in,
because *"a filter can be bypassed or forgotten; a shape that cannot express markup cannot carry
an injection."*

**Falsify the corpus premise before converting anything.** ADR-001 line 76, ADR-002 §2 and
00-ADMIN-IA §2 all assert *"all **18** bullets across three experience entries contain only
`<strong>`."* Measured against `data/resume.json` this session, that is two claims and only one
survives:

- **The count is wrong.** There are **13** bullets — Brevo 6, PharmEasy 3, MAQ 4 — carrying **17**
  `<strong>` runs. Commit `24afda2 content(resume): cut Brevo to the six bullets carrying a figure`
  cut Brevo from 11 to 6 *after* all three documents were written. **12 of 13** bullets contain
  markup; `experience[1].bullets[2]` (PharmEasy, the recommendation-system line) contains none — so
  a converter that assumed every bullet has at least one tag would be wrong about exactly one
  record, which is the hardest kind of wrong to see in a diff.
- **The "only `<strong>`" claim holds.** A tag census over the whole file returns `{strong: 34}` and
  nothing else — 17 open, 17 close, balanced, none nested, none with whitespace against a
  delimiter — and **no bullet contains `*`, `_`, `` ` ``, `[` or `]`**. So the converter has one tag
  to handle and today's data raises no escaping question. The escaping still has to be answered,
  because the Phase 7 editor writes new data and G-4's finding is about *silent* loss.

Output: one grammar module, a third vitest project for tests that need neither `workerd` nor a
built site, 13 converted bullets, and two independent proofs that the conversion moved the
encoding of emphasis and nothing else.
</objective>

**The vitest project contract, and why this plan must extend it.** `vitest.config.ts` composes two

| Project | Glob | Runtime |
|---|---|---|
| `workers` | `test/**/*.workerd.test.ts` | real `workerd` via `@cloudflare/vitest-pool-workers` |
| `integration` | `test/**/*.node.test.ts` | Node, with a `globalSetup` that runs a **full `astro build`** and spawns `astro preview` (`hookTimeout: 300_000`) |

`vitest.workers.config.ts` states the contract in prose: *"the two globs may never overlap and
every `*.test.ts` under `test/` must match exactly one of them."*

A unit test of a string grammar belongs in neither — putting it in `integration` makes every
assertion about a regex wait on a production build. So this plan adds a **third** project, `unit`,
glob `test/**/*.unit.test.ts`, no `globalSetup`. Mutual exclusivity is preserved because
`.unit.test.ts` matches neither existing glob. Plans 03-04 through 03-08 all use it.

**Why a vitest test and not `node -e` for anything importing `src/`.** `package.json` pins
`engines.node >= 22.12.0`, where TypeScript type-stripping is still behind a flag. A `node -e`
one-liner that imports `src/lib/bullets.ts` is a coin flip on the local Node build. Vitest
transpiles TS for free and is already the project's test runner — every assertion in this plan that
touches `src/` therefore lives in a `.unit.test.ts` file, and the `<verify>` blocks invoke vitest.

**`astro/zod` is available and is Zod 4.** `node_modules/astro/package.json` declares
`"./zod": "./dist/zod.js"` with `zod: ^4.3.6`; the resolved copy is **4.4.3**. This plan does not
use zod — 03-06 does — but `src/lib/bullets.ts` will be imported by a zod schema that runs during
prerender inside `workerd`, so it must carry **no Node-only imports**.

Design constraints, each with its reason:

- **`**` is the only production.** No `_`, no `` ` ``, no `[]()`, no `#`, no `<`. Everything else is
  literal text. This is the property that makes the shape unable to carry markup: there is no
  production that emits an angle bracket, so no parse of any input can produce one.
- **Escaping.** A literal `*` in run text serialises as `\*` and a literal `\` as `\\`; the parser
  reverses both. Today's corpus contains zero `*` characters, so this is dead code against current
  data — and it is exactly the code that stops being dead the first time someone types "5 * 3" into
  the Phase 7 editor. Write it now, while nothing is pressing.
- **Unbalanced `**` throws.** Do not silently treat a lone `**` as a literal. G-4 is a finding about
  *silent* loss; a throw is the difference between a save that fails visibly and one that quietly
  drops a run.
- **No Node-only imports** — this runs in `workerd` during prerender.
- **Do not write a renderer here.** `parseBullet` returns data. Turning runs into React elements is
  plan 03-07's job and lives in a component. Keeping them apart is what lets 03-07 prove the render
  boundary independently of the grammar.

**Do not use jsdom and do not set `environment: 'jsdom'`.** These are string functions; a DOM adds
nothing, and this project's register says a rendered claim verified in jsdom is not verified.
Rendering is 03-07's, via `renderToStaticMarkup` — the real server path, not a browser simulation.

**Design the round-trip suite so a degenerate implementation cannot pass it.** A suite that only

round-tripped string: a string-only assertion is the "34 tests all focused the first item" defect in
another costume, because the identity function satisfies every string round-trip there is. The
fixture set must include the six shapes named in `<behavior>`.
