<objective>
Make the existing test suite survive a 40th photograph **without weakening a single migration
proof**.

Measured in `04-RESEARCH.md`: appending one schema-valid 40th record turns **15 tests across 4
files red while `astro build` stays green**, and `scripts/migrate-photo-origin.mjs --verify`
exits 1. Nothing else in Phase 4 can be verified end to end until this is true, which is why
this is Wave 0 and why it runs before any pipeline code exists.

**The fix is not `39 → 40`.** One of the failing assertions says so in its own failure message:

> `these ids did not exist at ${previous.ref.slice(0,7)}, so this migration did not derive their
> rank; re-scope or retire this block rather than weakening it`
> — `test/content/photo-enrichment.unit.test.ts:340`

Every one of the 15 assertions gets classified, individually, as exactly one of:

| Class | Meaning | Shape after this plan |
|---|---|---|
| **cohort** | It proves something about the 39 records a migration moved. A photo published later was never in scope. | Iterate the cohort id set (the brief rows / the pre-migration revision), never `manifest`. |
| **floor** | It exists to stop the corpus silently emptying. | `>= 39` with the reason written beside it, the shape `scripts/assert-no-r2dev-urls.mjs:103` already uses correctly (it passes at 40 today). |
| **invariant** | It is true of every record forever. | Iterate the whole manifest, plus an anti-vacuity floor so an emptied file still fails. |

Purpose: unblock PIPE-01 and PIPE-03. A pipeline that appends a record to a manifest whose own
test suite forbids a 40th record cannot be verified at all.
Output: four re-scoped test files, a re-scoped migration script, and a standing growth proof
that fails the day someone reintroduces a hardcoded corpus size.
</objective>

**Shell discipline for every command in this plan.** The developer's interactive shell is
**zsh**; GitHub Actions runs **bash**. Never `${PIPESTATUS[0]}` (zsh spells it
`${pipestatus[1]}`, and `test -eq 0` against an empty expansion is a syntax error). Never
`R=$?` after a compound command — exit code 2 leaks into a `test "$R" = "1"`. Never
`( cmd && R=0 || R=1 )` — the assignment happens in a subshell and the parent always takes the
FAIL branch, which is how 13 negative controls in Phase 3 reported failure for correct code.
Capture an exit code only as: `if cmd; then R=0; else R=1; fi`.
