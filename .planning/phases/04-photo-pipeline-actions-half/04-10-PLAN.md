**Measurement hazards that will produce a false result here.** All were hit in this project.

1. **HEAD lies about caching.** `curl -sSI` returns `cf-cache-status: DYNAMIC` and **no
   `cache-control` header**, reproducibly over three objects × three tries. Only GET reveals
   `max-age=14400`. **Every cache assertion in this plan uses GET.**
2. **The shell here is zsh; Actions runs bash.** `npx $cmd` with `cmd="astro sync"` passes ONE argv
   element in zsh and "fails" in 245 ms. Do not use `${PIPESTATUS[0]}` (bash-only; in zsh it expands
   to nothing and `test -eq 0` is a syntax error). Do not write `( cmd && R=0 || R=1 )` — the
   assignment happens in a subshell and the parent always takes FAIL. Use
   `if cmd; then R=0; else R=1; fi`, and **state the shell for every control you run**.
3. **`grep -c` prints `0` and exits 1** on a zero count, so "returns 0" inverts as a condition.
   Use `! grep -q`.
4. **Expiry can never be proven by observation.** R2 lifecycle granularity is **days** and removal
   lags ~24 h. A test asserting an object disappeared would be a test that sleeps for a day.
   **Do not write one.** The only honest gate is the prefix comparison in Task 3.
5. **A red build leaves the previous `dist/` on disk.** After any failed step here, do not hand-run
   `wrangler deploy` — it would ship the last good artefact.

Write `scripts/assert-staging-lifecycle.mjs`.

**The command surface, measured — do not assume a JSON mode exists.** `wrangler r2 bucket lifecycle
list` has **no `--json` flag**; the only option is `-J, --jurisdiction`. Verified:

```
$ npx wrangler r2 bucket lifecycle list portfolio-photos --json
✘ [ERROR] Unknown argument: json          # exit 1
```

It emits human-readable text, one blank-line-separated block per rule:

```
name:     Default Multipart Abort Rule
enabled:  Yes
prefix:   (all prefixes)
action:   Abort incomplete multipart uploads after 7 days
```

Parse that. Note `prefix:   (all prefixes)` is a **rendered placeholder for the empty string**, not a
literal prefix — treat it as `''` and never as a match. If parsing rendered text is judged too
brittle, the alternative is the REST API `GET /accounts/{id}/r2/buckets/{name}/lifecycle`, which does
return JSON; **state in the summary which surface you used and why.**

**Assert all three of these, and fail naming which one was missing:**

1. `rule.prefix === STAGING_PREFIX` — **byte equality.** `startsWith` is rejected: a rule on `''`
   matches every key and would expire published photographs.
2. `rule.enabled === true` — a disabled rule satisfies every other check and expires nothing.
3. The rule carries an **expiry** action with **days > 0** — i.e. it deletes objects.

**Point 3 is the one that makes this gate real, and it was missing.** `lifecycle add` offers three
independent actions — `--expire-days`, `--ia-transition-days`, `--abort-multipart-days`. A rule with
`prefix: temp/` and only `--abort-multipart-days 7` expires **no objects** while satisfying prefix
equality and `enabled` perfectly. This is not hypothetical: `portfolio-photos` **already carries such
a rule today** — `name: Default Multipart Abort Rule`, `enabled: Yes`, `prefix: (all prefixes)`,
`action: Abort incomplete multipart uploads after 7 days`. One mistyped flag in Task 2's command
produces exactly that shape scoped to `temp/`, and a prefix-only gate goes green over it.

So: match the action text against an **expiry** form (`Expire objects after N days`), require `N > 0`,
and explicitly **reject** a rule whose only action is a multipart abort or a storage-class transition.

**Printing is not asserting.** The earlier version said the script "prints the matched rule's prefix,
its expiry in days, and the constant it was compared against" — a rule with no expiry has no
expiry-in-days to print, and nothing failed on that. Print all three for legibility **and** assert
each one.

Import `STAGING_PREFIX` **and** `STAGING_BUCKET` from `src/lib/photo-pipeline.ts`. The bucket name
has a single source — `wrangler.jsonc` `"bucket_name": "portfolio-photos"` — and the earlier version

prevent. If `STAGING_BUCKET` and `STAGING_EXPIRE_DAYS` are not yet exported, 04-02 owns
