      [DS-BARREL] Any import whose specifier is exactly `@akhil-saxena/design-system` or
        `@akhil-saxena/design-system/hooks` fails. `@akhil-saxena/design-system/icons` and
        `@akhil-saxena/design-system/components/<Name>` and any `.css` subpath are permitted.
        ENUMERATE THE PERMITTED SHAPE — match the specifier against
        /^@akhil-saxena\/design-system\/(icons|components\/[A-Za-z][A-Za-z0-9]*|[a-z0-9./-]+\.css|css\/[a-z0-9-]+)$/
        and fail anything that does not match, rather than deny-listing the barrel string. A
        deny-list was defeated three ways in Phase 4 with the guard silent; the permitted set here
        is small and closed. Cover both `import … from '…'` and `import '…'` side-effect form, and
        both quote styles even though biome enforces single quotes — 03-06 shipped four predicates
        that could not fire because they matched only double quotes.

      [DS-CLASS] Any `.astro` file containing a design-system component element with a `class=`
        attribute fails, naming the file, the line and the component. `<Card class="wk-card">`
        renders `class="ds-atom-card"` with no error, no warning and a plausible-looking page —
        Phase 0 lost this twice and `querySelectorAll('.wk-card').length` was 0. Derive the
        component-name set from the identifiers actually imported from
        `@akhil-saxena/design-system/components/*` in that same file, so the rule cannot go stale
        against a component nobody has used yet, and so it cannot fire on an app component that
        happens to share a name.

    Report with `process.stdout.write`, never `console.log` — under this repo's vitest setup
    console output prints nothing, and a gate reporting through it is indistinguishable from a
    gate that found nothing (STATE.md, found by 04-01).
    Refuse to pass against an empty or missing scan root: exit 1 with "scan root matched no files".
    Self-check each rule against its own canary before scanning, the way
    `assert-no-raw-html-sinks.mjs` does — a rule whose pattern does not match its own canary would
