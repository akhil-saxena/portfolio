<objective>
Make the variant table readable from a prerendered page without dragging `node:crypto` behind it,
and put the `srcset`/`sizes` arithmetic in one module that reads the same numbers the layout CSS
will.

Purpose: two of §16's eight owed measurements land here. §7.4 records an UNVERIFIED — whether a
prerendered Astro page can import `src/lib/photo-pipeline.ts` cleanly under the Cloudflare adapter,
given its module-scope `import { createHash } from 'node:crypto'` — and says to **measure it in the
first Phase 5 wave**. §5.3 assertion 5 then demands that `photo-pipeline.ts` appear in no client
chunk. A page cannot state widths as literals either: §7.4 measured that resize is by width,
capped, never enlarged, so the descriptor for every variant is exactly
`Math.min(variant.maxWidth, photo.dimensions.width)` and no served size needs storing.

And `sizes` must agree with the layout or the browser downloads the wrong file silently. That means
the gutter and gap numbers need one home before the CSS is written, not after.

Output: three small modules, one re-export, two suites.
</objective>

    `srcsetFor` is exactly §7.4's expression:

      VARIANTS.map(v => `${photo.urls[v.urlKey]} ${Math.min(v.maxWidth, photo.dimensions.width)}w`)

    `dimensions` supplies the RATIO and the descriptor arithmetic and nothing else — §7.2's ruling.
    Do not emit `width`/`height` attributes from anything downstream of this module and do not add a

    `width={photo.dimensions.width}` on an `<img>` whose `src` is `urls.original` states 4608 for a

    for each rung, content = `min(100vw, ${PAGE_MAX.photos}px)` at the top rung and `100vw` below

    rest. Emit the final unconditioned clause as `calc(100vw - ${2×baseGutter}px)`.

    A `sizes` that disagrees with the layout is a silently wrong download size — nothing renders
    incorrectly, the browser just fetches the wrong file. That is why it is derived here and gated
