<interfaces>
MEASURED 2026-08-28 against the published tarball. Four of these correct the UI-SPEC, and the
first is load-bearing.

**1. `--ds-appbar-h` is NOT reachable from a sibling, so §6.2 as written cannot work.**

`dist/client/css/appbar.css` declares it on the component's own class:

    .ds-atom-appbar { --ds-appbar-h: 47px; min-height: var(--ds-appbar-h); ... }
    @media (pointer: coarse) {
      .ds-atom-appbar a { min-height: 44px; min-width: 44px; }
      .ds-atom-appbar:has(a) { --ds-appbar-h: 69px; }
    }

Custom properties inherit DOWN, not sideways. A full-viewport section under `<main>` is a SIBLING
of the bar, so `calc(100svh - var(--ds-appbar-h))` there resolves against an undefined property,
the declaration is invalid at computed-value time, and `min-height` silently falls back to `auto`.
That produces a plausible-looking page with no error anywhere — the same class of failure as
`class=` versus `className=`.

The component's own comment names the consumer use case it cannot serve: *"a consumer building a
full-viewport landing needs `min-height: calc(100svh - var(--ds-appbar-h))`"*. So this is a
design-system finding, not a portfolio problem. Task 1 measures it, files it, and takes a mechanism
that needs no number at all.

**2. `Button` has no `as` prop.** `dist/components/Button.d.ts` is
`ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement>` with `variant`, `size`, `loading`,
`icon` and nothing else. §11.1's `<Button as="a" href="/resume.pdf" download>` is not
implementable. `Link` does have `as`. Recorded here because the shell starts the finding register;
plan 05-10 owns the résumé download control and the decision about it.

**3. Astro named slots become props on a framework component.** That is how `AppBar`'s `logo`,
`nav` and `actions` — all `ReactNode` — get filled from `.astro` with no `.tsx` wrapper. Measure
it; if it does not work, `src/components/public/PublicNav.tsx` rendered with NO `client:*`
directive is the fallback and ships zero JS either way (§1.3: `"use client"` is inert in Astro
without a directive). `FilterNav` cannot use the slot route at all — its `label: ReactNode` lives
inside an array prop — which is why plan 05-07 needs a wrapper regardless.

**4. `HeadingSizeToken` stops at `"4xl"` (44px)** while the scale ships `--text-4xl-plus` 52 and
`--text-5xl` 60. Home's 60px name has no token on `Heading`; use the legacy numeric `size={60}`
(which drives an inline style) or an app class, and record which.

Component signatures, measured:

    Footer     { variant?: "compact" | "expanded", copyright?, links?: Array<{label, href?, onClick?}>, columns?, className?, style? }
    Link       { variant?: "default" | "inline" | "footer" | "action" | "quiet", color?, as?, ...AnchorHTMLAttributes }

    Eyebrow    { size?: "xs"|"sm"|"md", tone?: "muted"|"accent" }

`Link`, `Card` and `Chip` all CONCATENATE `className` (chunk-6X5ZERPL, chunk-JOCBILNT,
