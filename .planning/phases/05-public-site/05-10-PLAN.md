<objective>
Build `/resume`: the whole record from `resume.json`, the PDF for the recruiter who wants the file,
a print stylesheet that produces a résumé rather than a screenshot of a website, and `Person`
structured data that needs no script tag.

Purpose: three requirements and one open decision. The page stays for two reasons the roadmap
amendment gives — Home's Act 2 holds work AND résumé in one viewport, so removing the page empties
half the mechanism, and an HTML résumé is crawlable and linkable where a PDF is neither. SEO-02 is
the interesting part: §12.3 measured with `@astrojs/compiler` that **Astro does not interpolate an
expression inside a `<script>` body** — a plain `{j}` ships to the page as the literal two
characters — and `set:html`, the only construct that does work, is banned by `gate:sinks` in use
form with no allowlist path. OQ-2 resolves that as microdata, which needs no sink at all.

Output: one route, one entry component, one stylesheet, one HTTP suite.
</objective>

<interfaces>
MEASURED against the committed data and the published tarball.

`resume.json` is `{ experience, skills, education }` and nothing else. **There is no prose summary
field**, so the page states the shape of the record rather than paraphrasing it. Inventing a summary
sentence would put copy on the page that exists in no fixture and that nobody owns.

Measured corpus: three experience entries, **13 bullets** (6 + 3 + 4), zero `<` characters, 17 bold
spans, **one literal `&`** (`upsell & cross-sell` in `pharmeasy#2`), longest bullet 141 characters.
Three skill groups. One education entry with `leadership` bullets. `public/resume.pdf` exists.

**Do not add an escaper.** React escapes text children by construction; a second one would
double-encode that `&` into `&amp;amp;` and render visibly wrong. The existing suite already asserts
the rendered corpus contains exactly one `&`.

**⚠ `Button` has NO `as` prop.** `dist/components/Button.d.ts` is
`ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement>` with `variant`, `size`, `loading`,
`icon` and nothing else. §11.1's `<Button as="a" href="/resume.pdf" download>` **is not
implementable**. `Link` does have `as`. This is a design-system finding and task 1 owns the decision;
it must not be closed by hand-rolling a button-shaped anchor with local CSS, which is exactly the
bespoke-over-design-system trade the Core Value forbids.

Astro compiler behaviour, MEASURED with the installed `@astrojs/compiler` (§12.3):

    plain expr in ld+json   $$render`<script type="application/ld+json">{j}</script>`
    is:inline + expr        $$render`<script type="application/ld+json">{j}</script>`
    set:html                $$render`<script type="application/ld+json">${$$unescapeHTML(j)}</script>`
    define:vars             $$render`<script ...>(function(){${$$defineScriptVars({j})}...})();</script>`

The first two ship the literal characters `{j}` to the page — a naive implementation ships broken
JSON-LD and every gate passes. `define:vars` wraps the body in an IIFE, which is not valid JSON.
</interfaces>
