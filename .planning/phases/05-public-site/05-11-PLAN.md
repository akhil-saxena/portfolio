<interfaces>
**The full-viewport mechanism is NOT `calc(100svh - var(--ds-appbar-h))`.** Plan 05-06 measured that
`--ds-appbar-h` is declared on `.ds-atom-appbar`, so a sibling section under `<main>` cannot read it
and the declaration is invalid at computed-value time — `min-height` silently falls back to `auto`,
producing a plausible page with no error. §6.2 as written cannot work. The shell instead establishes:

    .pub-shell { min-height: 100svh; display: flex; flex-direction: column; }
    .pub-main  { flex: 1 1 auto; display: flex; flex-direction: column; }

so this plan writes `.hm-a { flex: 1 0 auto; }` and nothing else for the budget. Read 05-06's
SUMMARY for the measured resolved value before starting, and if it found the property DOES resolve,
use whichever mechanism 05-06 actually shipped.

All three of §6.2's load-bearing properties survive and must be preserved:
  - `svh`, never `vh`, never `dvh`. `100vh` is the LARGE viewport, so at first paint on iOS Safari
    and Android Chrome the scroll prompt — the one element whose entire job is to be visible at
    first paint — is pushed below the fold. `dvh` changes DURING a scroll, moving a transition's own
    target distance mid-gesture.
  - `min-height`, never `height`. `flex: 1 0 auto` cannot shrink, so content taller than the budget
    overflows VISIBLY. A visible overflow is a failure a screenshot catches; a clip is one it hides.
  - the chrome above comes out of the budget — structurally here, which is more accurate than a
    constant that is 47px on fine pointers and 69px on coarse.

**The peek arrangement — column count is a function of available HEIGHT, and the naive instinct is
backwards.** Fewer columns means more rows means taller. CARRIED, measured in a real browser at all
six classes:

Column count steps on the WIDTH rungs 375 / 673 / 1024. **Tile aspect steps on a HEIGHT rung at
800px.** That is not an aspect-ratio branch — it is a query on the axis the budget is denominated in.
3:2 at 1024×768 needs 418px of gallery against 637px minus ~246px of chrome; it does not fit, and at
900px tall it does. Gap is `--space-4` (16px) at every class.

**The peek grid is a grid at every class and NEVER a horizontal rail.** A rail fits any budget, which
is what makes it tempting, and it nests a horizontal scroller inside this page's vertical snap
container — on iOS a horizontal rail readily steals the vertical gesture. `/photos` IS a rail at
classes 1–2 precisely because it has no vertical snap container. Same pattern, opposite verdict, and
the reason is the container.
