frontmatter and passed finished, which is exactly what §7.4's import constraint requires and what

  <action>
    A thin React component that renders **nothing of its own until opened**.

      - Import `Lightbox` from `@akhil-saxena/design-system/components/Lightbox` — the subpath, never
        the barrel. `scripts/assert-ds-import-contract.mjs` enforces it and plan 05-14 re-checks the
        built chunks independently, because "should not" is not evidence.
      - Props: `items` (a JSON-serialisable array carrying `src`, `alt`, `srcSet`, `sizes`, the six
        EXIF fields and `place`) and `gridSelector` (a string).
      - On mount, attach ONE delegated `click` listener to the element matched by `gridSelector`.
        Open at the tile's `data-lb-index` **only** on a modified-key-free left click — no
        `metaKey`, `ctrlKey`, `shiftKey` or `altKey`, and `button === 0`. Anything else falls through
        to the anchor, so cmd-click still opens the prerendered page in a new tab.
      - Call `preventDefault()` **only once it has opened.** If the open path throws or bails, the
        anchor must still navigate. That ordering is the difference between a progressive
        enhancement and a broken link.
      - **Push a history entry on open and close on `popstate`**, so the Back button dismisses the
        lightbox rather than leaving the page. Without it the Back-button guarantee holds for the
        no-JS path and breaks for the JS path — which is worse than not having it, because it works
        until it does not.
      - Build each `LightboxItem.caption` in React from `exifRows(item.exif)` plus `place`. Same
        omit-null rule, same single implementation: **an item whose `exifRows` is empty gets no
        caption at all**, not an empty one. `product-peppers` is the case.
      - Do NOT import `src/lib/photo-pipeline.ts`, directly or transitively. `srcSet` and `sizes`
        arrive as finished strings.
      - Do NOT override the always-dark invariant.
      - Any transition this component adds respects `prefers-reduced-motion`; the design system
        exposes `useReducedMotion` from `@akhil-saxena/design-system/hooks` — but note that the
        hooks subpath is a barrel of its own, so check its module graph before importing it, and
        prefer a plain `matchMedia` read if it drags anything unexpected in.
  </action>
