<interfaces>
**The 301 mechanism, and why the obvious one is wrong.** Astro's `redirects` config under a static
output emits an HTML page carrying a `<meta http-equiv="refresh">`. SEO-05 explicitly rejects that:
*"must be a real 301, not a meta-refresh page."* Cloudflare Workers Static Assets reads a
`_redirects` file from the assets directory, and Astro copies `public/` into `dist/client/` verbatim, so:

    public/_redirects:
      /portfolio  /photos  301

**Verify the status code against a runtime that serves `_redirects`.** `astro preview` does not —
it is a plain static server. This repository's `astro dev` runs real `workerd` (see CLAUDE.md), and
`wrangler dev` does too. Assert with `curl -sI` against one of those, **not against the source and
not against `astro preview`**, and quote the status line.

**The OG image is not this plan's to choose.** OQ-6a was resolved as `architecture-singapore`'s
`large` variant and implemented in plan 05-06 as `src/lib/site-meta.ts`, wired as `<Seo>`'s default.
This plan asserts the outcome on every built page. Stated here so the assertion's expected value is
not re-derived from scratch: it is `urls.large` of the record whose id is `architecture-singapore`,
read from the manifest at test time and never pasted.

**Route census, MEASURED 2026-08-28** and stated only so the sitemap's count can be confirmed:

    /  ·  /work  ·  /photos  ·  /resume            4
    /photos/<category>   7 categories              7
    /photos/<category>/<slug>   40 photographs    40
                                                  ---
                                                   51 URLs

**The corpus is at 40 records, not the 39 the UI-SPEC quotes** (Phase 4's `wildlife-gentlegiants`),
so §12.3's "49-URL sitemap" is already stale by two. **Derive the expected count in the test from
the data; do not write 49, 51, 40 or 7.** 03-01's `--verify` hardcoded 39 and STATE.md flagged it;
04-09 wrote a new hardcoded count and the first real photograph turned `main` red.

`/404` must NOT appear in the sitemap. Configure the sitemap's filter to exclude it, and assert the
exclusion — a sitemap advertising a 404 page is a crawl-budget bug that no build error catches.
</interfaces>

| T-05-13-01 | Spoofing (open redirect) | `public/_redirects` | mitigate | The rule is a single literal source path to a single literal same-origin target. No wildcard capture is placed into the destination, which is the construct that turns a redirect file into an open redirect |

| T-05-13-03 | Spoofing | `og:url` / canonical | mitigate | Built from `Astro.site` by `<Seo>`, which throws on anything it cannot make absolute |
