# Phase 5 — every design-system finding, in one place

**Target: `@akhil-saxena/design-system@2.0.0-beta.2`.** Measured against the published
**`2.0.0-beta.1`** as installed in this repository, which is the version Phase 5 ships on.

**NONE OF THESE BLOCKS PHASE 5.** Every one of them ships as-is. That is the Core Value working
rather than failing: *"if a tradeoff arises between shipping something bespoke and shipping it out
of the design system, the design system wins, and any gap it exposes is a finding rather than a
workaround."* Twenty gaps, twenty findings, zero `!important`, zero re-implemented components, zero
local forks. This file is the input to a `2.0.0-beta.2`; it is not a list of blockers.

Read out of the plan summaries `05-06` … `05-13` and re-verified against the installed package
before being written down — every citation below was opened, not remembered. Paths are relative to
`node_modules/@akhil-saxena/design-system/` unless stated.

| **D-2** | **`--ds-appbar-h` is declared on `.ds-atom-appbar`, so a sibling cannot read it — which is the one use case its own docstring names.** And the declared value is itself wrong. | `dist/primitives.css:5560-5584` — the docstring at 5560 tells a consumer to write `min-height: calc(100svh - var(--ds-appbar-h))`; the declaration at 5584 is inside the bar's own rule. | **D-3** | **OQ-4 — `FilterNav` misses the 44px coarse-pointer floor, and a consumer cannot reach its anchors.** | `dist/primitives.css:3638-3641` — `.ds-atom-segmented[data-size="lg"] .ds-atom-segmented-btn { height: 40px }`. | **D-7** | **`HeadingSizeToken` stops at `4xl` while the scale ships `4xl-plus` and `5xl`.** | `dist/components/Heading.d.ts:6` — `"2xs" \| … \| "4xl"`. `dist/tokens.css:212` ships `--text-4xl-plus: 52px` and the file also ships `--text-5xl: 60px`. | The component's own token union does not expose two steps its own type scale defines. | **D-8** | **The theme has no `@media print` block and no `data-force-light` hook (OQ-5's residual).** | Measured across `dist/themes/monochrome.css`, `dist/primitives.css` and `dist/tokens.css`: `@media print` occurs **0** times in all three; `force-light` occurs **0** times. | CSS cannot un-`.dark` a page, so a dark-mode résumé prints dark unless JavaScript removes the class. ## What this phase did NOT do about any of them

- **No `!important` in any stylesheet.** Checked: `git grep -c '!important' -- src/styles/` matches
  **nothing**. The token occurs three times under `src/`, and all three are PROSE explaining why it
  was not used — `ExifList.astro:56`, `PhotoLightbox.tsx:94`, `ProjectCard.astro:83`.
- **No component re-implemented, no component forked, no second component library.**
- **No local copy of a design-system token value** — `--ds-appbar-h` is deliberately *not* restated
  in `public-shell.css`, which forbids it by name (D-2), and `--hm-above` is an over-estimated
  allowance instead.
- **The one local copy that does exist is D-1's theme script**, which is written to be deleted and
  says so at the rule.

Every gap above is reachable through a component's own documented API, or is carried as a measured
shortfall that ships. That is the disposition the Core Value asks for, and this document is the
receipt.
