## OD-12 differential corpus: THE VERDICT

> **The differential corpus is NOT available.** Not one of the 39 live objects carries any EXIF.
> The proof OD-12 called "unusually cheap" cannot be run at any price, because the bytes it was to
> be run against were discarded in 2026-03 when the legacy encoder wrote WebP without
> `withMetadata()`. This is not a drift result and must not be read as one.

`04-RESEARCH.md`'s resolution table makes the differential proof **mandatory** for OD-12 option B:

> *"re-extract EXIF from the 39 live originals and require all six fields to reproduce the
> committed values byte-for-byte, nulls included — `camera` null on 1, `lens` on 11, `aperture` on
> 2, `shutter` on 2, `iso` on 2, `focalLength` on 2."*

The plan (04-04 Task 1) suspected the premise was false and required it measured **before** the
decision was taken, because *"a decision resting on an unavailable proof is worse than a decision
taken without one."* It was measured. The premise is false.

### The probe

All 39 `urls.original` objects were fetched with **GET** (a body is required, and HEAD cannot carry
one — `04-VALIDATION.md` hazard 1 and `scripts/verify-photo-urls.mjs`'s frozen mode table both say
liveness is HEAD's job and this is not a liveness question). The origin was **read from
`src/lib/image-origin.ts`**, never hand-typed — threat `T-04-16`. Each object was then read by two
independent readers, so the library's answer is not taken on trust:

1. `sharp(buf).metadata().exif` — the library-level answer.
2. A raw RIFF chunk walk listing every fourcc in the container — the byte-level answer.

Reproduce with (from the repo root):

```bash
node --input-type=module -e '
import sharp from "sharp";
import { readFileSync } from "node:fs";
const ORIGIN = readFileSync("src/lib/image-origin.ts","utf8")
  .match(/export const IMAGE_ORIGIN = .([^"'"'"']+)./)[1];
const chunks = (b) => {
  if (b.toString("ascii",0,4)!=="RIFF"||b.toString("ascii",8,12)!=="WEBP") return ["not-riff"];
  const out=[]; let o=12;
  while (o+8<=b.length){const f=b.toString("ascii",o,o+4);const s=b.readUInt32LE(o+4);
    out.push(f.trim()+":"+s); o+=8+s+(s%2);} return out;
};
for (const p of JSON.parse(readFileSync("data/portfolio_images.json","utf8"))) {
  const u = new URL(p.urls.original);
  if (u.origin !== ORIGIN) throw new Error("non-canonical origin refused: "+u.origin);
  const buf = Buffer.from(await (await fetch(u.href,{method:"GET"})).arrayBuffer());
  const m = await sharp(buf).metadata();
  process.stdout.write(p.id+"  exif="+(m.exif?m.exif.length+"B":"ABSENT")+
    "  chunks=["+chunks(buf).join(" ")+"]\n");
}'
```

### The result — 39 of 39, no exceptions

Full per-record output is in **`exif-differential.txt`** (39 rows). Every row is identical in the
only respect that matters:

```
abstract-intothemist  0/6  sharp.exif=ABSENT  riff-EXIF-chunk=ABSENT  chunks=[VP8:28406]     committed-non-null=6/6
architecture-redbuilding  0/6  sharp.exif=ABSENT  riff-EXIF-chunk=ABSENT  chunks=[VP8:329024]  committed-non-null=1/6
product-peppers  0/6  sharp.exif=ABSENT  riff-EXIF-chunk=ABSENT  chunks=[VP8:83082]  committed-non-null=0/6
```

- **39/39 fetched 200 `image/webp`.** Zero 404s, so this is a real absence and not an absent file.
- **39/39 report `sharp.exif=ABSENT`.**
- **39/39 contain exactly ONE RIFF chunk — the `VP8` image data.** No `EXIF`, no `XMP`, no `ICCP`.
  There is no container slot in which metadata could be hiding from sharp.

The container header confirms it byte-for-byte — `VP8 ` begins at offset 12, immediately after
`WEBP`, so nothing precedes the image data:

```
$ curl -sS "https://images.akhilsaxena.com/photos/product/peppers.webp" | head -c 20 | xxd
00000000: 5249 4646 9644 0100 5745 4250 5650 3820  RIFF.D..WEBPVP8
00000010: 8a44 0100                                .D..
```

### Why — the mechanism, not a guess

`git show legacy/nextjs-portfolio:scripts/process-images.js` encodes every variant as

```js
.resize({ width, withoutEnlargement: true })
.webp({ quality: variant.quality })
```

with **no `withMetadata()` and no `keepMetadata()` anywhere in the file** (grepped: zero hits for
`withMetadata`, `withExif`, `keepMetadata`, `keepExif`). sharp strips metadata by default. So the
EXIF was read once from the camera original, mapped to the six schema fields, written into
`portfolio_images.json` — and then discarded along with the source file, which was never committed
(`git ls-tree -r --name-only legacy/nextjs-portfolio` under `new-photos/` returns only `.gitkeep`).

**The 39 committed `exif` blocks are the only surviving record of those bytes.** They are the
output of the extraction, not an input any extraction can be re-run against.

### What OD-12 option B must therefore be proved against instead

The plan named the fallback: *"the fixtures this plan builds, plus a synthetic-input test of the
mapper"* — and noted that needing it **materially strengthens option A**. Two things were done so
that as much of the mandatory proof as is recoverable was in fact recovered:

1. **The fixtures** (`rich-exif.jpg`, `no-exif.jpg`) exercise `exif-reader` end-to-end against the
   expectation table in `expected-exif.json`, which is written from the same source values the
   generator writes into the file — so the file and the expectation cannot drift apart.
2. **A cross-library differential**, run once in a throwaway directory (see below). This is the
   nearest available substitute for the 39-record proof: it asks the same question OD-12 asked —
   *"did the library change the mapping?"* — by running the legacy `exifr` extractor, verbatim,
   beside the new `exif-reader` one and requiring the six mapped fields to be identical.

It is weaker than the 39-record proof in one specific, stated way: it proves the two libraries
**agree with each other** on a file this repository constructed, not that either agrees with 39
photographs a human reviewed in 2026-03. Nothing available can prove the latter.

## Cross-library differential — the recovered substitute proof

Run in a **throwaway directory**, never in this repository (`04-VALIDATION.md` hazard 5:
`slopcheck install` is not a dry run and modified this tree once during research; the same caution
is applied to any exploratory install). **`exifr` was NOT added to this repository's
`package.json`** — it was installed only in the throwaway tree, purely to be the reference
implementation for this comparison, and the tree was discarded afterwards.

The reference implementation is the legacy `extractExif`, copied verbatim from
`git show legacy/nextjs-portfolio:scripts/process-images.js`:

```js
const data = await exifr.parse(filePath, {
  pick: ["Make","Model","LensModel","FNumber","ExposureTime","ISO","FocalLength"], gps: false });
if (!data) return null;
return {
  camera: [data.Make, data.Model].filter(Boolean).join(" ") || null,
  lens: data.LensModel || null,
  aperture: data.FNumber ? `f/${data.FNumber}` : null,
  shutter: data.ExposureTime ? (data.ExposureTime < 1
    ? `1/${Math.round(1 / data.ExposureTime)}` : `${data.ExposureTime}s`) : null,
  iso: data.ISO || null,
  focalLength: data.FocalLength ? `${data.FocalLength}mm` : null,
};
```
